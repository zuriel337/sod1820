## Important inventory caveat: books

The current production schema does not expose a single canonical `books` / `book_pages` inventory that can safely answer "how many books/pages have been scanned". OCR exists strongly on the gallery corpus (2,558 images; 2,539 with OCR text), but this must NOT be publicly relabeled as book-page coverage without proving provenance.

Therefore the navigation may show the Books & Sources world now, but public counters for books/pages/analysis-ready books remain **measurement pending** until their canonical source is located or defined. No guessed counter.

## One knowledge body, many entrances

number → word → person → verse → source → code → research → relationship

A visitor can start at any point. Menus provide explicit navigation; Raziel provides conversational navigation; Heichal provides spatial navigation; the graph/tree is the common relationship substrate.

## Progress contract

Do not hard-code decorative progress percentages as truth.

Each world eventually gets canonical milestones:
- inventory coverage
- search/index coverage
- relationship coverage
- UI availability
- AI/context availability
- spatial/3D availability

Only then calculate a public percentage.

Until then use explicit states:
- LIVE
- בפיתוח
- בקרוב
- מדידה בהכנה

Home build map, mega-menu meters and bottom SOD1820 V2 meter must eventually read from the same canonical source.

## Immediate UI payload for System Frame V1

Mega menus should already show:
1. what works now;
2. measured scale where trustworthy;
3. what is being built;
4. future doors in the correct world;
5. a short sentence explaining why the world matters.

This lets the existing 15-year knowledge corpus become visible immediately while preserving a truthful preview of the much larger system being built.
