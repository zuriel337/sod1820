## Known evaluation difference and remaining gates

Moving calculation after page selection necessarily changes error propagation for malformed data outside that page. An explicit regression fixture demonstrates: baseline raises `22000` because a non-selected composite is invalid; candidate successfully returns the valid selected atomic row. Errors in selected composites still propagate identically. This known behavior must remain visible in activation review; universal error equivalence is not claimed, and the client must not conceal genuine permission/calculation errors with fallback.

The remaining match count and method classification still inspect the complete eligible set. Unlimited calls still calculate every returned composite. This does not eliminate all database work.

No claim is made about native PostgreSQL 17.6 plans, full production corpus parity, concurrent load, RPC latency, scrolling, or navigation. Before production activation, validate the deployed additive function on representative permitted inputs and measure the same 2029 routes with the switch OFF/ON. The current candidate remains OFF by default. Rollback at the application level is the existing switch OFF; it returns callers to the unchanged secure baseline.
