# ELS advanced research: implementation handoff

Branch: `codex/els-research-advanced-v1`. Parent: Claude ELS visual commit `10c9af5ed9c8bf2eaaec0df0d17b61c63bd927f0`. The Classic structure remains unchanged; the canonical ELS engine now accepts a read-only exact-skip probe from Research. No merge or production deployment.

The Research profile offers explicit Torah/Tanakh page search with a user-chosen skip range and a page size (1–100) in one search form. The old near/medium/far presets and separate disclosure boxes are gone; exact skip and related-word actions remain in the same form. The bridge's arbitrary 500 maximum has been removed in this branch; Postgres's integer input and the corpus's physical length are the only skip bounds. Each request is still user initiated, rate-gated, page-sized and traced. This bridge change is **branch-only** until the Edge Function is separately released; the deployed service may still reject ranges above 500 in preview. The client does not generate ELS occurrences. A selected hit is reverified through the existing `els_occurrence_replay_v1` path before the engine receives an exact `load-matrix` item. Raziel remains an explicit user action from the verified context.
There is no total result/page count ceiling within the selected skip range: the user can keep loading pages until the server marks the range complete. The UI shows loaded pages and hits and rejects an incomplete page, repeated cursor or duplicate hits instead of incorrectly claiming that browsing finished. Tanakh page search support must be checked against the live canonical RPC before claiming it is available. A browser fixture exercises three consecutive keyset pages and verifies the exact continuation sequence.

The next Research slice adds a user-initiated comparison of two to four terms in the same explicit scope and skip range. It uses the existing `els2029AdaptiveScanner` with at most one page and one canonical bridge call per term, hard trial/candidate/wall budgets and `POST_HOC_EXPLORATORY` selection provenance. The UI distinguishes empty, partial and failed results. It does not label separate hits as a convergence or compute a significance claim. The existing matrix cross tool remains the place to inspect a chosen primary axis against another word. Each batch hit still passes exact verification before the shared matrix loads it.

Research also offers an exact-skip request. It first sends `{term, scope, skip, requestId}` to the already mounted canonical engine for a nonmutating probe. The engine uses `fixedSkipCandidates` and `promoteVerified`/`verify_batch`, then returns a verified exact anchor tied to the request ID. Only that anchor enters the existing `load-matrix` path. A failed probe leaves the displayed matrix untouched; a failed exact replay restores the previous display state. A real-corpus browser test found `תורה קדשה` at skip 10065 and canonical start 50890. This mode opens one occurrence at the requested skip; it is not an exhaustive count of every occurrence at that skip. The unified form also offers explicit spelling transformations: full reversal, reversal inside every word, and reversal of the last word. These produce distinct search terms and then use the same canonical page/verification path; they are separate from the engine's existing reverse *reading direction*.

Only the Research panel renders these new controls. The same native matrix and engine stay mounted during profile changes, and the Advanced form and results remain available when returning to Research. Opening a saved cipher clears the Advanced load item so the saved cipher wins. Existing findings, color, selection, source, save and navigation controls remain owned by the native Classic workspace.
