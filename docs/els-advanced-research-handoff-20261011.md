# ELS advanced research: implementation handoff

Branch: `codex/els-research-advanced-v1`. Parent: Claude ELS visual commit `10c9af5ed9c8bf2eaaec0df0d17b61c63bd927f0`. The Classic structure remains unchanged; the canonical ELS engine now accepts a read-only exact-skip probe from Research. No merge or production deployment.

The Research profile now offers explicit, bounded Torah/Tanakh page search. Users can choose a custom skip range (2–500), one of three range presets, and a page size (1–100). The next page uses the server's exact keyset cursor. Results come only from `els_search_page_v1` through `els-search-bridge`; the client does not generate ELS occurrences. A selected hit is reverified through the existing `els_occurrence_replay_v1` path before the existing engine receives an exact `load-matrix` item. Once its canonical state reaches Research Context, the existing exact replay/layers path enables the existing contextual Raziel entry. Raziel remains an explicit user action.
There is no total result/page count ceiling within the selected skip range: the user can keep loading pages until the server marks the range complete. The UI shows loaded pages and hits and rejects an incomplete page, repeated cursor or duplicate hits instead of incorrectly claiming that browsing finished. Each page still has a bounded size and the backend currently limits the skip range to 500; Tanakh page search still returns `MISSING_ADAPTER` from the existing backend. A browser fixture exercises three consecutive keyset pages and verifies the exact continuation sequence.

The next Research slice adds a user-initiated comparison of two to four terms in the same explicit scope and skip range. It uses the existing `els2029AdaptiveScanner` with at most one page and one canonical bridge call per term, hard trial/candidate/wall budgets and `POST_HOC_EXPLORATORY` selection provenance. The UI distinguishes empty, partial and failed results. It does not label separate hits as a convergence or compute a significance claim. The existing matrix cross tool remains the place to inspect a chosen primary axis against another word. Each batch hit still passes exact verification before the shared matrix loads it.

Research also offers an exact-skip request without the page bridge's arbitrary 500 ceiling. It first sends `{term, scope, skip, requestId}` to the already mounted canonical engine for a nonmutating probe. The engine uses `fixedSkipCandidates` and `promoteVerified`/`verify_batch`, then returns a verified exact anchor tied to the request ID. Only that anchor enters the existing `load-matrix` path. A failed probe leaves the displayed matrix untouched; a failed exact replay restores the previous display state. A real-corpus browser test found `תורה קדשה` at skip 10065 and canonical start 50890. This mode opens one occurrence at the requested skip; it is not an exhaustive count of every occurrence at that skip. Full-domain open-range enumeration is still constrained by the bridge's explicit page policy and remains a separate backend/release task.

Only the Research panel renders these new controls. The same native matrix and engine stay mounted during profile changes, and the Advanced form and results remain available when returning to Research. Opening a saved cipher clears the Advanced load item so the saved cipher wins. Existing findings, color, selection, source, save and navigation controls remain owned by the native Classic workspace.
