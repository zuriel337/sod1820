# SOD1820 — ELS Classic Matrix / Research Matrix Projection Contract v1

**Status:** Human-Gate ZURIEL direction · 2026-09-27 · implementation branch only until merged.  
**Owner check:** EXTEND_EXISTING under `els_research_layer_law v9`, `research_workspace_law v4`, `experience_governance_foundation_v1_law v7` and visual owner `SOD1820_DESIGN_CONTRACT_V1.md`.  
**No new engine/store/truth/UI owner.**

## Decision

ELS 2029 has one canonical engine and one governed Research State. It exposes two primary interaction profiles over that same state:

- **Classic Matrix** — fast, direct, familiar 2D/manual work.
- **Research Matrix** — the default 2029 capability envelope: the same matrix plus progressive research depth.

These are profiles, not products or truth systems.

## Classic Matrix

Classic preserves the useful familiar matrix capability family:
- exact 2D matrix and primary axis/findings;
- pan / zoom / fit / focus;
- direct occurrence inspection;
- manual finding actions;
- source / verse context;
- low-cost direct interaction.

Classic does not, merely by opening:
- start adaptive expansion;
- run Matrix Volume searches;
- invoke Raziel/AI;
- run expensive controls/nulls/background research.

The current legacy/classic renderer may remain temporarily as a compatibility projection while 2029 absorbs capability. Its route/DOM/CSS is not canonical and must not become a permanent second runtime.

## Research Matrix

Research is the default profile for 2029 verified ELS work.

Its initial state remains simple: primary 2D matrix first. It progressively exposes, when useful:
- Layered / 2.5D relations;
- Vector Geometry;
- Slice Shift;
- Dynamic Matrix Volume;
- motifs / intersections / parallel families;
- adaptive bounded research actions;
- controls / challenge;
- optional Raziel explanation/planning.

Research does not equal AI and does not equal 3D. It works deterministically without either.

Entering Research is not a compute trigger. Heavy work requires an explicit action or qualified bounded plan/signal under the active ELS/Research Strategy owners.

## Lossless transition

`Classic ↔ Research` must preserve the same:
- corpus / corpus version;
- Anchor / occurrence identity;
- exact replay result;
- findings and dependency groups;
- selection;
- matrix geometry;
- portable viewport/focus;
- Journey / Research Context;
- saved research references.

A profile switch never creates evidence, truth, a new Finding or a new dependency group.

Research-only projections may be hidden in Classic without being deleted. Returning to Research restores already-computed governed state.

## Orthogonal axes

Interaction profile and renderer are separate:

- Classic is normally 2D.
- Research may be 2D, Layered or future 3D.
- Research can stay 2D forever.
- 3D never implies stronger truth.
- AI availability never changes profile identity.

## Default and user agency

2029 defaults to **Research Matrix**, because it is the complete capability envelope, but the opening experience is minimal/direct and low-cost.

The user may switch to **Classic Matrix** at any time. Future persistence of this preference belongs to the Experience preference owner; this contract does not create a preference store.

No forced AI. No forced 3D. No forced deep scan.

## Acceptance before UI cutover

1. Research is the default profile and performs no heavy I/O merely on entry.
2. Classic exposes only the direct baseline capability profile.
3. Classic/Research transitions preserve the same state identity and do not require replay.
4. Hidden Research data survives a Classic round trip.
5. AI availability changes optional actions only.
6. Profile choice changes neither truth nor evidence.
7. No second ELS engine/store/runtime is created.
8. Visual treatment is implemented later under the Design Contract after overlapping writers are clear.

## Research Bundle v1 and Compact Geometry First — 24.10.2026

Research result ordering, nearby-finding discovery and structural groups now share one additive presentation law: `els_compact_geometry_priority_v1`.

- **Stage A — compact:** every consecutive letter occupies a neighbouring matrix cell. With primary width `S`, this includes horizontal `1`, vertical `S`, diagonal `S-1` / `S+1`, and literal intersections whose participating paths are themselves compact.
- **Stage B — spaced:** `gridStep > 1`, including `2S`, `S±2` and wider gaps. These remain available for inspection but cannot displace Stage A in a bounded top list.
- Corpus skip and visual gap are different facts. A large skip `S` can be visually gapless; a multiple such as `2S` is not.
- This law ranks inspection order only. It does not verify a candidate, change historical quality scores, create a Finding or assert meaning/truth.

`els_research_bundle_v1` composes existing projections without a new engine or store:

1. A matching public saved cipher is shown before raw occurrences when its stored selected anchors produce a research-ready compact package. The public `els_records` gallery projection remains the only source; the bundle exports counts/reasons and a public route, never coordinates.
2. Exact same-path continuation and compact geometry govern the top-three result triage. For a
   regular search, continuation triage covers every occurrence already admitted by that completed
   canonical search, not only the visible 80-item page; the bridge still projects only the current
   page plus a bounded list of research targets. Every admitted result remains available.
   The continuation check includes a canonical Torah word touching the verified axis immediately
   before or after it, including bounded two- and three-letter words that are excluded from broad
   matrix discovery because they are too noisy there. A touching word may form a before, after or
   combined two-sided research target; it remains a candidate until the existing verifier admits it.
3. Choosing an exact continuation as a research target is one explicit action. The engine resolves
   the coordinate-free choice back to its internal occurrence, canonically verifies the complete
   expression, and only then opens that exact anchor through the existing C02 `load-matrix` path.
   The matrix remains visible and the ranked result context is retained for exact return.
4. The candidate scan is chunked, reports progress and can be cancelled without changing the matrix.
5. The same explicit package scan feeds the existing nearby-finding list and the bounded structural
   grouping projection. It does not run on Research entry. Candidate terms still pass canonical
   verification before they can become Findings.
6. `חזור בדיוק לתוצאות` restores the previous axis, findings, selection geometry and view through
   the existing Journey snapshot, then reopens Results. No parallel navigation state is introduced.
7. When at least two exact continuations are available, one explicit comparison action may resolve
   and canonically verify two to four of those already-discovered targets. The default presentation
   compares the first three. It reports every verified/failed row separately, preserves
   `POST_HOC_EXPLORATORY` provenance and makes no significance or Truth claim. Opening a verified
   row reuses that exact verification, enters the ordinary bundle/Journey path and returns to the
   same result context. Comparison is transient projection state: it creates no matrix copy, store,
   Finding, research object or second engine, and performs no work on Research entry.

Within each stage, distance and existing governed research evidence remain deterministic tie-breakers. Structural groups are Stage A only when every member is compact; mixed/spaced groups follow in Stage B. B12/B13, full 3D, Raziel wiring, `research_objects`, DB/RLS/permission changes and production migration remain outside this contract.

Golden evidence: the public cipher `יום משיח בא` at `S=583` has six selected secondary findings — three at `S`, two at `1`, and one at `S+1`. Therefore its live projection is `6/6` Stage A (three vertical, two horizontal, one diagonal) and must rank ahead of a package with more but spaced findings.

## Axis Neighborhood Research Bundle v1 — 24.10.2026

`els_axis_neighborhood_bundle_v1` replaces the narrow “nearby findings with continuation” view with
one matrix-local Research package. It is anchored to the currently verified primary occurrence and
reads the displayed matrix itself; it does not depend on a matching saved cipher or require a local
candidate to have another dictionary word continuing on its own path.

The deterministic inspection order is:

1. compact vertical/diagonal parallels to the primary axis;
2. compact paths intersecting the primary axis;
3. other compact horizontal or adjacent paths;
4. spaced structures, retained as Stage B.

Distance is the first tie-breaker inside each band. Existing verified/public research support may
break later ties but cannot displace a closer structural band, so an old saved record is evidence,
not a discovery prerequisite. Two- and three-word phrases are kept as a compact normalized index
derived lazily from canonical verse text. A phrase candidate is materialized only when a word path
already found inside the local matrix extends across its exact canonical word boundaries; the
phrase index is not brute-force scanned as a second matrix search. Basic Hebrew-year forms are
generated deterministically for the omitted-thousands range and labelled only as possible year
patterns. Both remain candidates until the ordinary canonical verifier admits an exact occurrence.

The same explicit action also projects bounded local structure groups. When at least three compact
terms form a nearby cluster, the package may suggest one of them as a better local research axis.
The suggestion is calculated automatically, but the matrix never moves automatically: one user
action resolves the coordinate-free term again inside the canonical engine, verifies it, opens it
through the existing C02/Journey seam, and preserves exact return. A stale or failed suggestion
leaves the current matrix unchanged.

Regular and cross-search results use this identical package after the user opens a result or
meeting. There is no cross-specific candidate engine, ranking, state or store. The package remains
Research-only, bounded, cancellable and visible-progress work; entering Research performs no scan.
Classic stays available over the same engine and state. The boundary exports labels, declared
bands, explanations and verified hit identity, never candidate cell arrays or start coordinates.

This contract does not implement B12/B13, full 3D, `research_objects`, Raziel, schema/data changes,
RLS/permissions, Production migrations or `decision_ledger`, and it does not make a significance,
meaning or Truth claim.

## Focused Core Bundle v1 — 25.10.2026

`els_focused_core_bundle_v1` is the default first pass of the existing axis-neighborhood action.
It bounds work relative to the verified axis rather than imposing an unrelated absolute skip cap:
12 rows and 15 columns around the axis, exact source sequence `1`, and the compact skip family
`S−1`, `S`, `S+1`, in both reading directions. The previous displayed-window scan remains available
only through the explicit **הרחב עוד טבעת** action.

The first package is capped at 12 verification attempts and deliberately reserves bounded lanes
for exact source phrases, governed/core words, canonical Biblical words, possible Hebrew-year
forms, morphology and local exact compounds. This prevents one dense verse row or one candidate
class from consuming the complete package. Every ELS row passes the existing canonical verifier;
a `skip=1` row is admitted only after exact literal source replay. Each projected row exposes its
skip, reading direction, structural relationship to `S`, verification status and at most three
source verses. Cell arrays and start coordinates remain internal to the canonical engine.

Vocabulary is derived from the canonical Tanakh language even when occurrence scope is Torah.
That broadens words and bounded spelling/morphology candidates only: a Tanakh vocabulary word must
still occur and verify inside the active Torah scope before it can be presented as an ELS result.
Runtime discovery removes `visible_saved_research` and `verified_research` sources. Historical
saved ciphers are cold Golden fixtures only and never feed candidate generation or ranking.

The cold Goldens are `משיח טבת עשירי`, `יום משיח בא` and `קולומביה`. Their recorded axes
are replayed against the canonical corpus with an empty saved-matrix input. Acceptance requires
independent rediscovery of the known structural terms, including `אליהו`, `תשעו`,
`לכפר עליכם`, `ספינת`, `יכל אש` and `אש אכלה`. A Golden proves recall and
contract stability, not meaning, statistical significance or a privileged runtime answer.

Progress has separate `core`, `verify` and `sources` phases and remains cancellable. No work starts
on profile entry. The slice adds no engine, store, graph, Provider, Journey, database object,
permission or RLS change. B12/B13, numeric interpretation, Raziel and semantic explanation remain
separate consumers after this structural base.

## Saved Evidence Replay and Local Gap Stage B — 25.10.2026

A saved matrix is replay evidence, not a request to rediscover its primary term across the complete
corpus. The canonical load order is now:

1. verify one recorded exact anchor when `start`, direction and skip are present;
2. otherwise enumerate only the recorded skip and canonically verify those candidates;
3. accept a legacy skip directly only when that verification has one governed occurrence;
4. retain broad discovery solely as the ambiguity/missing-evidence fallback.

Historical rows labelled `torah` may contain explicit saved Finding coordinates that continue into
Joshua or Judges. Only the compatibility adapter may select Tanakh as their smallest containing
replay scope. The stored Torah corpus identity is accepted in that one disclosed case, and the
primary axis is then verified again against the containing canonical corpus. Every other corpus
mismatch remains fail-closed. Replay does not mutate the saved row, infer a new coordinate or copy
the matrix. Saved Finding identities are restored exactly; a contiguous `skip=1` occurrence remains
a source sequence and is not relabelled as ELS.

Focused Core Stage A remains the compact family `1`, `S−1`, `S` and `S+1`. A bounded Stage B now
starts local gaps `2…8` only within two axis rows and eight columns of the primary column; every
result must still remain inside the fixed 12-row/15-column core. Stage B cannot displace the compact
ordering and receives at most one reserved admission seat in the first package. It exists to retain
a nearby deliberate gap such as `חשמל` without reopening the old broad displayed-window scan.

The cold Golden set now also includes `תורת הרמז` at `S=21940`. With saved-matrix vocabulary absent,
the canonical corpus scan rediscovers `נשמהללוט` and `זרע` in Stage A and `חשמל` in bounded Stage B;
the Stage B probe count must remain below 8,000. A saved historical replay must restore all three,
including the source-sequence presentation of `זרע`, through one fixed-skip axis verification.

This refinement adds no engine, state, store, graph, Provider, Journey, schema, data rewrite, RLS or
permission change. It makes no semantic, statistical or Truth claim. Broader Hirsch material may be
admitted as cold Goldens only after each axis and Finding has independently replayable coordinates;
it must never become runtime vocabulary or privileged ranking input.

## Hirsch cold-Golden admission and focused width — 25.10.2026

Hirsch evidence is admitted in two separate test-only grades. `T1_EXACT_REPLAY` requires one
independently recovered primary occurrence plus exact replay of every selected Finding inside the
declared corpus. `T2_COLD_RECALL` additionally requires the complete pre-admission candidate pool of
the existing focused scanner to rediscover the recorded occurrence from canonical language with
`CLOUD_MATRICES=[]`. It is not a promise that a human-curated semantic relation will occupy one of
the first 12 structural seats. Passing either grade is a structural regression proof only; it is
not an author endorsement, interpretation, significance score or Truth claim.

Three public legacy records satisfy both grades: `מוטאטיל` at `7887_-1_59154`, `ז׳ אוקטובר` at
`42168_-1_600006`, and `אטום טיל` at `10044_-1_102070`. Their legacy database rows still have no
`start_index` or `corpus_id`; the recovered identities live only in the cold test fixture and do not
rewrite those rows. Every recorded Finding is replayed exactly. The five `skip=1` findings under
`ז׳ אוקטובר` remain literal source sequences and are never labelled ELS. The historical
`תשפ״ו אלול חיבור בו הותר` row is a negative control: although its axis can be replayed, its stored
quality is unverified and it has no Findings, so it cannot become a positive Golden.

The evidence exposed a generic geometry boundary, not a vocabulary gap: `פלשתימ` is 14 columns
from the `ז׳ אוקטובר` axis and `משיח` is 15 columns from the `אטום טיל` axis. The focused core is
therefore widened from 12 to 15 columns while keeping `rowPad=12`, the 12-admission cap, and the
Stage B start window unchanged at two rows/eight columns. Every cold-Golden axis must stay below
12,000 local probes. A separate hard runtime ceiling of 16,384 probes lets a longer verified
extension finish that same bounded geometry; it does not widen the window. The eligible candidate
pool has a separate 32,768 emergency ceiling; exceeding either runtime budget fails closed and
returns no partial package. Canonical-language construction, candidate materialization, origin
scanning, candidate projection and stable ranking yield in bounded chunks with count-only,
phase-stable progress and cancellation. One derived line-context index is reused across the bounded
admitted package instead of being rebuilt for every row. Saved/public terms remain stripped from runtime candidate generation, and a poisoned
saved-only term must not change the exact rediscovered Hirsch occurrences. The visible selector is
structurally mixed and path-diverse; semantic comparison belongs to a later consumer such as Raziel,
not to an author/title-specific runtime rule.

A future pinned activity meter may retain a stopped package only at the canonical-verification
boundary: verified admissions may remain as an explicitly partial draft, while raw candidates must
never be coloured, persisted or described as Findings. That checkpointed-stop behavior is not part
of this refinement; cancellation here remains fail-closed.

This is a bounded refinement of F03 and the existing Research bundle, not a new capability. It adds
no engine, state, store, graph, Provider, Journey, schema, migration, data rewrite, RLS, permission,
`research_objects`, Raziel or `decision_ledger` change.

## Axis-source context and repeated topic projection — 25.10.2026

A verified primary occurrence carries a small deterministic source-context probe. Explicit words
of four or more Hebrew letters in the active query, plus three-letter terms already present in the
governed core vocabulary, are checked only in the canonical verses traversed by the verified axis
cells. A match is an exact contiguous `skip=1` source sequence. It is projected with the complete
canonical verse and the label **פסוק מקור באותו הקשר**; it is never inferred from a saved cipher,
an author title or an AI answer. This lets an axis such as `יום שבת תשמור` disclose `שבת` in a
traversed Sabbath verse, and lets a query such as `בלעם הרשע` retain a literal `בלעם` match even
when the longer expression is not present contiguously in the source.

The probe does not widen the 12-row/15-column ELS scan. Its bound is the finite set of axis-touched
verses, and at most 24 exact source occurrences are collected. Up to two topic-context terms receive
reserved admission in the first package. Repeated occurrences of the same topic participate in the
existing motif and result-triage projections, so multiple occurrences are ranked together while
rank-don't-hide keeps every other search result available. Coordinates remain internal; public
projection exposes the exact verse, declared source relationship and occurrence count only.

Literal context detection is intentionally deterministic and precedes any future semantic consumer.
Raziel or another approved S6 consumer may later explain non-literal relations (for example an entity
and its associated event vocabulary), but it may not invent an occurrence or replace canonical
verification. The old open-ended **המשך סריקה מסודרת עד דילוג 100** control is removed from the
regular-results rail: focused Research remains axis-relative, bounded and cancellable, with wider
work available only through its explicit bounded expansion controls.

This refinement changes no engine, store, state graph, schema, data, RLS, permissions or Production
configuration, and it makes no meaning, significance or Truth claim.

## Checkpointed Research activity v1 — 25.10.2026

The existing Research progress surface is now one pinned, colour-coded activity projection for
regular search, cross search, automatic plans and the focused axis package. It reports the current
bounded phase, elapsed time, completed work and the count of canonically admitted rows. Updates stay
batched; scrolling the page or the local findings rail does not hide the active meter.

Focused-package cancellation remains fail-closed before canonical admission. Once an individual row
has passed the existing verifier, the same engine operation may expose that already-safe projection
inside an explicitly labelled **partial verified draft**. Raw candidates, coordinates and starts do
not cross the bridge, do not colour the matrix and never become Findings. Stopping leaves the axis,
Findings, source geometry and selection unchanged.

One in-memory operation checkpoint is retained inside the already-mounted canonical engine. Resume
is accepted only when scope, exact primary occurrence and deterministic selected-candidate signature
still match. It continues after the last completed verification attempt and merges no host-supplied
truth. A new axis, scope, candidate signature or ordinary fresh package request discards the
checkpoint. Completion replaces the draft with the ordinary complete package.

The checkpoint is ephemeral presentation/operation state: it is not persisted, synced, written to
Research Context or treated as an ELS/Research store. It adds no engine, Provider, graph, Journey,
schema, RLS, permission or Truth transition.
