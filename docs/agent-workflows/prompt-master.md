# SOD1820 Prompt Master — pilot v0.1

A workflow aid, not a new contract, authority, queue, or permission. Use only for substantial task scoping, resumption, or handoff preparation; skip trivial questions and routine edits unless explicitly requested. Default to Hebrew, concise output, and direct execution only within existing user authorization.

1. Read the applicable AGENTS.md / CLAUDE.md and SOD1820_MASTER_OWNER_INDEX.md routing instructions. Resolve current canonical owner and direct dependencies only. Do not duplicate or override them. Verify live rule versions when needed.
2. For substantial work, verify the current repo/base/head and authorized bounded work_log_current access; check task completion, active scope/path overlap and open PRs. If coordination cannot be verified, report COORDINATION_UNVERIFIED and restrict to read-only. Do not assume a summary is live evidence.
3. Preserve user intent, explicit constraints, and unresolved choices. Convert the request to the smallest useful task brief: goal, intended actor/lane (per existing owner rules), scope, non-goals, exact relevant sources/IDs, acceptance tests, authorization boundary, and stop conditions. Mark unknowns; never invent IDs, measurements, or permissions.
4. Prefer evidence reuse and minimal context; avoid repeated audits, whole-history scans, unnecessary agents, and long restatements. Use deterministic tools for deterministic work. Do not claim savings without measurement.
5. Follow one scope/one active writer; use existing isolated-branch and release gates. No automatic agent activation, dispatch, GPT ACK, new coordination mechanism, or escalation of permissions. Reports go to ZURIEL; passive BEFORE/AFTER only through an authorized writer under current law. No claim of delivery without evidence.
6. For a prompt-only request, produce the brief without executing the task. For an execution request, follow existing authorization and verification gates; never reinterpret prompt optimization as permission to merge, deploy, change DB, or bypass tests.
7. At completion, state actual status, exact evidence, tests run/not run, blockers, and next step. Do not collapse documented, committed, merged, deployed, live, verified.

## Pilot checks
- "Fix the homepage speed" → bounded owner/scope, evidence and performance gate; no deployment.
- "Continue from handoff ID X" → retrieve exact authorized record; verify current state; no invented ACK.
- "Change a title" → skip skill unless requested; no broad context scan.
- "Claude and Codex both change the same component" → identify overlap and report, no duplicate write.
- "Publish now" → preserve exact approval gates; no implied release authorization.

Compare matched tasks with and without skill: input/output tokens or provider usage where exposed, elapsed time, repeated reads, rework, and acceptance quality. Missing telemetry = unknown. No savings claim before evidence.
