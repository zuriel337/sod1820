# בדיקת האתר לפי בקשה

נוהל העבודה הקיים נמצא ב־[CLAUDE.md §0.6](../CLAUDE.md#06-בדיקות-דפדפן-מול-האתר-החי-zuriel-26112026--הרחבה-של-04-לא-חוזה-נוסף). הנוהל הזה מתאר את פקודת הבדיקה ואת ההכנה הדרושה להפעלת חשבון הבדיקה.

## ״בדוק את האתר״

בסביבת Codex הייעודית `sod1820`, משתמשים ב־Chromium ו־Playwright של הסביבה. במידת הצורך אפשר להתקין את גרסת Playwright שכבר משמשת את בדיקות הדפדפן ב־CI עם `npm install --no-save playwright@1.55.0`.

```sh
node scripts/check-site-2029.mjs
```

ההרצה פותחת דפדפן חדש כאורח. היא סוקרת את מפת האתר, פותחת את המדורים הציבוריים ודוגמה מכל משפחת תוכן שנבדקת, ומריצה את המדורים המרכזיים במחשב, ברוחב 390 פיקסלים ובאמולציית Pixel 7. אם הדפדפן מקבל 401, 403 או 429, מדווחים על החסימה ועל הכיסוי שהושלם. אין לשנות מדיניות רשת או הגנות כדי להעביר בדיקה. מספר הכתובות במפת האתר מציין את היקף המלאי, ובדיקות הדפדפן מדווחות על הכתובות שנפתחו בפועל.

שער הפריסה [Post-Deploy Canary](../.github/workflows/post-deploy-canary.yml) ובדיקות ההתחברות המדומות ב־[CI](../.github/workflows/live-contracts-2029.yml) ממשיכים לשמש את תפקידיהם הקיימים. השוו את מקור הפריסה ב־Vercel לפני ואחרי בדיקה חיה אם התוצאה נועדה לקומיט מסוים.

## ״בדוק גם עם התחברות״

אפשר להריץ את [בדיקת חשבון הבדיקה](../.github/workflows/site-account-check-2029.yml) לאחר השלמת ההקמה והאישורים. ההרצה הידנית ב־GitHub משתמשת בקוד מ־`main` ובהרשאות קריאה למאגר. היא מתחברת במסלול הסיסמה הרגיל בגרסה המבודדת, מאמתת את מזהה המשתמש לאחר טעינה חוזרת ופותחת את ההודעות, ההתראות והמחקר. התוצאה מתארת פתיחה של המודולים. בדיקת קבלה של שמירה, מסירת הודעה או סימון קריאה דורשת פעולת בדיקה מתאימה על נתוני QA.

הפעלה חד־פעמית דורשת את הפרטים הבאים:

1. כתובת QA מבודדת ובסיס Supabase שאינו ייצור. נכון לבדיקת ההכנה, קוד האתר כולל הפניות קשיחות ל־Supabase של הייצור. לפני חיבור החשבון יש לוודא שגרסת QA מכוונת את האימות, ה־worker, פעולות הנתונים והתעבורה בצד השרת למסד המבודד. כתובת Preview לבדה אינה ראיה לבידוד.
2. חשבון QA רגיל עם מזהה קבוע וסיסמה אקראית, ללא הרשאת מנהל או מידע של משתמשים אמיתיים. מאמתים בחשבון ובמסד המבודד שההרשאות מוגבלות. תיעוד המסירה כולל יעד ושיטת ביטול הגישה בלבד.
3. סביבה מוגנת בשם `sod1820-qa` ב־GitHub Actions עם הרשאת הרצה מ־`main` בלבד. מגדירים שם את כתובות QA ו־Supabase כמשתני סביבה ואת מזהה החשבון, המייל והסיסמה כסודות מוגנים. הפעלת ההזנה הקבועה דורשת אישור מפורש להתאמה לדרישת `request_credential` שב־§0.6. אין להזין סוד בשיחה, בקוד או ביומן.

הרצה עם חשבון מסרבת ליעדי הייצור הידועים ודורשת מפתח אחסון של Supabase המבודד ומזהה חשבון תואם. היא אינה שומרת מצב התחברות, הקלטת רשת או תמונות מכילות מידע אישי. מבטלים גישה על ידי השבתת חשבון QA, ביטול ההתחברויות הקיימות והסרת הסוד מהסביבה המוגנת. מיזוג, שינוי תצורה, הגדרת סודות ופעולות כתיבה בייצור כפופים ל־§0.4 ול־§0.6.
