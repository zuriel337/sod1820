# בדיקת האתר לפי בקשה

נוהל העבודה הקיים נמצא ב־[CLAUDE.md §0.6](../CLAUDE.md#06-בדיקות-דפדפן-מול-האתר-החי-zuriel-26112026--הרחבה-של-04-לא-חוזה-נוסף). הנוהל הזה מתאר את פקודת הבדיקה ואת ההכנה הדרושה להפעלת חשבון הבדיקה.

## ״בדוק את האתר״

בסביבת Codex הייעודית `sod1820` משתמשים ב־Chromium ו־Playwright של הסביבה. כשהסביבה מקבלת 403, הבדיקה רצה על runner של GitHub (ראו למטה): הפקודה לסוכן היא `/check-site`.

```sh
node scripts/check-site-2029.mjs
```

ההרצה פותחת דפדפן חדש כאורח. היא סוקרת את מפת האתר, פותחת את המדורים הציבוריים ודוגמה מכל משפחת תוכן שנבדקת, ומריצה את המדורים המרכזיים במחשב, ברוחב 390 פיקסלים ובאמולציית Pixel 7. אם הדפדפן מקבל 401, 403 או 429, מדווחים על החסימה ועל הכיסוי שהושלם. אין לשנות מדיניות רשת או הגנות כדי להעביר בדיקה. מספר הכתובות במפת האתר מציין את היקף המלאי, ובדיקות הדפדפן מדווחות על הכתובות שנפתחו בפועל.

שער הפריסה [Post-Deploy Canary](../.github/workflows/post-deploy-canary.yml) ובדיקות ההתחברות המדומות ב־[CI](../.github/workflows/live-contracts-2029.yml) ממשיכים לשמש את תפקידיהם הקיימים. השוו את מקור הפריסה ב־Vercel לפני ואחרי בדיקה חיה אם התוצאה נועדה לקומיט מסוים.

## ״בדוק גם עם התחברות״ (סביבה מבודדת, ללא סודות)

[site-qa-2029.yml](../.github/workflows/site-qa-2029.yml) רץ ידנית ב־GitHub Actions וכל מה שהוא מקים נהרס עם ההרצה: Supabase מקומי וזמני (Docker: GoTrue ו־PostgREST בלבד, `qa/supabase`), תוצר הייצור הבנוי שמוגש בכתובות הייצור על ידי שרת ה־fixture הקיים (`test/helpers/authBrowserFixture.mjs`, עם מצב `supabaseProxy`), ו־Chromium שממפה את כתובת ה־Supabase של הייצור למסד המקומי ואת כל שאר הכתובות לכלום. הלקוח, ה־worker והקוד רצים ללא שינוי, ושום בקשה אינה מגיעה לייצור. חשבון הבדיקה סינתטי: `scripts/qa-site-2029.mjs` יוצר אותו ברגע ההרצה עם סיסמה אקראית שחיה רק בתהליך. אין סוד, אין GitHub Environment, ואין סיסמה או קוד בשיחה.

מה נבדק עכשיו (הוכח ב־CI, ריצה 45860804712): התחברות עם סיסמה וזהות זהה אחרי רענון, במחשב וב־Pixel 7; ושלוש דרגות פרסום הצופן מול PostgREST ו־GoTrue אמיתיים בסביבה המקומית, עם חשבונות סינתטיים (חבר, זר, מנהל): פרטי, העמוד שלי (אורח רואה בדפדפן אמיתי), בקשת ספרייה (ממתינה, פריט תור אחד, ביטול), אישור מנהל בלבד, משיכה, והרשאות (אנונימי ו־חבר נחסמים). לא נבדק: זרימת הממשק של לוח השמירה דרך המנוע (נשמרת דרך ה־RPC), ומכשיר אמיתי. סכימת ה־ELS נוצרת בזמן הריצה מ־SQL הקיים במאגר (`scripts/build-qa-schema.mjs`) ואינה נשמרת בקומיט. סכימת ה־QA (`qa/supabase/migrations`) היא של בדיקות בלבד ואינה מוחלת על הייצור.

## הרצה ב־GitHub (כשהסביבה חסומה) ומה נמצא (26.11.2026)

סביבות הסוכנים מקבלות 403 מהאתר, ולכן אותו סקריפט (`scripts/check-site-2029.mjs`, בלי עותק שני) רץ גם ב־[site-check-2029.yml](../.github/workflows/site-check-2029.yml) על runner של GitHub: ידני, הרשאת קריאה בלבד, בלי סודות. הפקודה לסוכן: `/check-site` (`.claude/commands/check-site.md`). הסקריפט ממשיך לפרופיל הבא אחרי חסימה ומדווח `BLOCKED_AT_EDGE` ושורת `EDGE` (כותרות וגוף קצר בלבד) שמזהה מי סירב.

מה הוכח ב־runner: מפת האתר תקינה (15 חלקים, כ־17,500 כתובות), ובדיקות HTTP של ה־canary עוברות. מהדפדפן: `desktop-1440` ו־`phone-390` מקבלים `403 Access denied` כי ה־User-Agent שלהם הוא `HeadlessChrome`, ו־`middleware-core.js` מסווג `headless`, `playwright`, `puppeteer` ו־`selenium` כבוט רע וחוסם (מכוון, ולכן הפרופילים האלה מסומנים כיסוי פתוח; ה־User-Agent אינו מזויף ושום הגנה לא שונתה). פרופיל המכשיר (`Pixel 7`, `iPhone 13`) נושא User-Agent רגיל ופתח את הבית ואת `/code`, `/codes` וצופן ציבורי; אבל Pixel 7 קיבל `403` גם על `/world` בלי שנמצא כלל שמסביר זאת (מדינות המדיניות הן CN ו־SG בלבד): נשאר ממצא פתוח לבדיקה. כל הסקריפט מוגבל לכתובות הציבוריות.

## בידוד וסביבת QA: מה קיים

- פרויקט Supabase יחיד (ייצור), ללא branches. הארגון בתוכנית Pro, ולכן פרויקט שני או branch הם בתשלום ודורשים אישור.
- הכתובת של Supabase קבועה לייצור ב־`src/lib/supabase.js` וב־`public-reading-deploy/transport.js`: כל build, כולל Preview, מדבר עם מסד הייצור. בידוד נוצר רק בבדיקות ה־CI באמצעות fixture שמיירט את הרשת (`startFixture`), כולל התחברות מדומה.
- לכן אין כרגע איפה להריץ התחברות אמיתית בלי לגעת בייצור, וה־workflow `site-account-check-2029.yml` מסרב מכוון לכל יעד ייצור.
- אפשרויות, לפי עלות (ההערכות אינן מאומתות מול החשבון): (1) מסד מקומי של Supabase בתוך GitHub Actions, בלי עלות, מצילום סכמה שנקרא מהייצור, עם דריסת כתובת בזמן build וגדר בדיקה שמונעת אותה בבניית ייצור; דורש שינוי קוד מאושר. (2) branch של Supabase (חיוב לפי שעה, כ־10 דולר לחודש אם נשאר פעיל). (3) פרויקט שני (חיוב חודשי). (4) חשבון ייעודי בייצור בשער reviewer: אינו מבודד, ודורש אישור לכל כתיבה.
