This is not a claim that every historical implementation status is still current. It is a **routing preservation table**.

For each old workstream it answers:

`old workstream → 2027 home → what survives → what does NOT auto-authorize`

Statuses such as LIVE/branch/open in the old v5.3 body must be reverified against current DB/main/work_log before implementation or release. A later Human-Gate decision may supersede presentation/priority while preserving the underlying capability.

The canonical parser test on current main enumerates **24 canonical WS cards**. Six additional named/subtrack workstreams that carry decision/gate semantics outside that parsed 24-card set are included below so no known gate disappears from v5.4 navigation.

Classification vocabulary:

- **CLOSED BASELINE** — historical foundation/result retained; no new build implied.
- **ABSORBED** — future work belongs inside a W0–W9 stage, not a parallel product program.
- **RETAINED SEPARATE** — still a separate foundation/security/content/research track.
- **PARKED / LATER** — preserve provenance/capability, no current build.
- **SUPERSEDED PRESENTATION** — old UI/phase form no longer controls future UI.
- **OPEN HUMAN GATE** — do not cross automatically; reverify the current form of the gate first.
