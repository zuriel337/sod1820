## Purpose

A Signature is the richer visual projection of an existing semantic identity. It is not a new category system, logo registry, truth badge, media store, or ontology.

Continuity target:

`functional icon -> Signature -> motion/depth -> later spatial representation`

The identity, label, route/context, truth, provenance and access semantics stay unchanged across visual richness tiers.

## Projection variants

- `compact`: chip/navigation/classification surface.
- `overlay`: image/post Hero corner signature; image art stays clean and the system overlays the signature after generation.
- `hero`: authored series/context mark on entry/major editorial surfaces.

Future T3/T4 spatial forms must extend the same identity rather than invent another logo.

## Category inheritance

Only a small set is mapped initially:

- `רמזים חזקים` -> `strong_hints`
- `סוד החשמל` -> `sod_hashmal`
- `צפונות בתורה` -> `els`

This mapping is presentation-only. Category identity remains in the existing content/category system.

## Truth and accessibility boundary

Signature means context/series identity only. It must never communicate or imply `verified`, `canonical`, `published`, confidence, truth rank, access tier, HOT/importance, or Human-Gate status.

Color/glow/depth/motion are visual language only. Reduced-motion fallback is mandatory; no required information may exist only in animation or higher spatial tiers.

## Migration

Legacy emoji/category icons remain compatibility presentation until each surface enters redesign. Do not mass-replace them blindly. New/redesigned surfaces should prefer Signature Family where a signature exists.
