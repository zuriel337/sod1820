## Target and parser gate

Structural validation now requires all of the following before hosted mode
reaches its explicit blocker:

- HTTPS-only arm origins with no credentials, path, query or fragment;
- exact immutable Wave3 Vercel deployment hosts and exact repeated
  `--allow-preview-origin` entries;
- canonical IP literals only, with port zero, scoped IPv6, IPv4-mapped IPv6,
  legacy numeric IPv4, shortened IPv4 and noncanonical IPv6 rejected;
- two different origins and two different exact 40-character SHAs in A/B mode;
- arm/auth origins disjoint from every database origin and from the known
  Production database origin;
- auth origin equal to its arm origin, with the corresponding stdin-token
  option;
- manually followed Preview-auth redirects with `max_redirects=0` at every
  hop. Only one-leading-slash origin-relative paths or parser-stable absolute
  HTTPS URLs are accepted. Raw or encoded slash/backslash ambiguity, controls,
  whitespace, fragments, userinfo, Unicode authority, scheme-relative forms,
  mixed slashes and origin/port changes fail closed.

This closes the reviewed `urllib`/WHATWG differential for backslash and mixed
slash forms that URL parsers can interpret as an external authority.

## Network boundary and the remaining blocker

The in-browser decision function remains default-deny for page traffic: it can
allow only reads to the exact arm origin, explicitly named database read
origins, and named read-only RPCs. Production is not implicit. Blocked records
contain classifications and hashes rather than raw hosts, URLs or paths.

That route is insufficient for hosted evidence once a Service Worker is
enabled. Service-Worker-owned network requests may bypass the
`BrowserContext` route, while the canonical Preview Worker itself allows broad
GET/HEAD/OPTIONS traffic. A valid hosted run therefore needs a separately
reviewed external proxy/firewall boundary, or a canonical measurement Worker
whose artifact and policy are verified before navigation. Neither contract
exists in this evidence-only scope. The runner consequently refuses all hosted
execution rather than presenting incomplete isolation as a PASS.

## Receipt privacy

The request ledger retains request state, resource and initiator type,
start/end/cutoff time, status and transfer/encoded/decoded byte counts. It does
not retain bodies, headers, cookies, query values, raw initiator URLs or free
error text.

Hosts and opaque path segments are fingerprinted. Only a narrow literal path
and query-key allowlist remains readable; suspicious keys and every other key
are fingerprinted. Unsupported schemes are omitted. Blocked requests use fixed
URL/path/host markers. Local distribution paths, initiator locations and error
details are hashes. LCP element IDs and class names are omitted.

Adversarial coverage includes token-like path segments and keys, naked secrets,
`sessionid`, FTP, raw/mixed/encoded slash and backslash redirects, controls and
whitespace, userinfo, Unicode/IDNA authorities, noncanonical IP forms, port
zero, redirect chains, SPA fallback HTML and artifact mutation.
