## Guard and bootstrap contract

The generated worker has two bound identities:

- Its URL carries the SHA-256 of the exact generated bytes: `/preview-readonly-sw.js?content=<sha256>`.
- Its challenge response carries the exact protocol, commit, branch, approved host, target, environment, RPC allowlist, guard identity, and worker content digest.

The bootstrap installs a page-level pending write guard before registration. It imports the application only after the newly generated worker is activated, controls the page, has the exact content-bound URL, is the registration's active worker, and returns the exact challenge response. Matching `scriptURL` alone is insufficient. A stale unsafe controller at the same expected URL cannot attest and cannot authorize the import. POST fetches, XHR, beacons, and POST forms remain blocked throughout install, update, activation, claim, and attestation.

One 8,000 ms deadline covers registration, worker fetch/install, activation, claim, and attestation. Expiry closes the bootstrap, prevents a late success from importing the application, keeps the transport guard closed, and renders the Hebrew fail-closed message. The executable stall test delays the worker response for 20 seconds and observes the visible failure before that response; the assertion permits a two-second browser scheduling margin around the configured deadline.

The service worker still allows only the reviewed read/auth surface. The exact compact Number reader `fn_number_opening_projection_2029` remains allowed; adjacent RPCs, table writes, same-origin writes, account mutations, and other product writes remain blocked.

## Exact build and source contract

`SOD_BUILD_TARGET` is now an external input. The integrated builder rejects a missing value and every value other than exact `2029` before importing Vite or creating output. It also preserves exact gates for:

- `VERCEL_ENV=preview`;
- `VERCEL_GIT_COMMIT_REF=gpt/perf-unified-wave4-preview-20261018`;
- a lowercase 40-hex `VERCEL_GIT_COMMIT_SHA` equal to checked-out `HEAD`;
- an approved exact SOD1820 Vercel Preview hostname in `VERCEL_URL`.

Before Vite or output, the builder inspects staged, unstaged, and nonignored untracked paths. It rejects every build-input difference, including additions below `public/`. Installed `node_modules` and ignored build caches may remain. The executable fixture proves that a tracked worker/builder edit with unchanged `HEAD`, an untracked `public/` file, and a staged public input each fail before Vite and leave no output.

## Number flag retry contract

The initial flag projection continues to use the shared navigation snapshot. Only a missing or malformed `lock_number` row in the exact approved Preview triggers one automatic uncached read targeted to:

`site_flags.select("key,enabled,message,mode").eq("key", "lock_number").limit(1)`

That read does not invalidate, replace, or notify the shared `site_flags`/runtime-switch snapshot. A second missing or malformed result fails closed. Manual retry issues exactly one targeted request per click, leaves its control visible and disabled while pending, and never starts a loop. Browser instrumentation proves zero extra shared reads and zero non-target requests or callbacks for `fx_now_feed`, `fx_analytics`, or any other switch. Legacy behavior is unchanged.

## Complete artifact binding

The build writes `preview-artifacts.json` with deterministic byte-order sorting and `path`, `size`, and SHA-256 for every one of the 256 deployed files. It covers `index.html`, `2029.html`, both worker names, the receipt, the inventory itself, all copied public files, and every Vite manifest asset.

The self-reference convention is explicit:

- Ordinary files hash their exact bytes.
- `preview-build.json` hashes the exact serialized bytes after only its `artifactInventorySha256` and `identitySha256` values are replaced by 64 zeroes.
- `preview-artifacts.json` hashes the exact serialized bytes after only its own `sha256` value is replaced by 64 zeroes.

The receipt identity binds the inventory root and artifact count. The standalone verifier rejects missing, extra, resized, or mutated deploy files. Executable tests copy the deploy tree and prove rejection of both an unexpected file and a mutated `index.html`.
