# כתובת חזרה מדויקת לפריוויו — שינוי משותף נדרש

הספקים Google ו־Facebook מופעלים ב־Supabase, וההרשמה מותרת. התחלת OAuth חזרה302 למסך הספק בשניהם. בזרימות הבדיקה האנונימיות, auth.flow_state שמר referrer של https://sod1820.co.il במקום כתובת הפריוויו; גם ביטול הכניסה חזר לאתר החי. לא נוצר משתמש ולא אושר חשבון ספק. זה אינו אימות של התחברות מוצלחת.

השינוי המצומצם המוצע ב־Authentication → URL Configuration → Redirect URLs בפרויקט linswmnnkjxvweumprav:

```text
APPEND EXACTLY:
https://sod1820-git-gpt-2029-functional-unifi-18c668-sod1820-s-projects.vercel.app/auth/callback
```

יש לשמר את Site URL ואת כל הכתובות הקיימות. אין להוסיף wildcard, דומיין אחר או הרשאות ספק נוספות. Google/Facebook ממשיכים להשתמש בכתובת callback של Supabase, ולכן אין שינוי מוצע בקונסולות הספקים. הדפדפן חוזר לכתובת הפריוויו המאומתת בלבד; יעד העמוד המקומי נשמר בנפרד ללא אסימונים, עם תוקף10דקות.

בדיקות אחרי שינוי: התחלה וביטול בכל ספק חוזרים לכתובת המדויקת; יעד זר אינו מתקבל; התחברות אמיתית באישור בעל החשבון, חזרה להקשר, יציאה מקומית והחלפת חשבון. בדיקות יחידה של יעד בטוח, תוקף, ערכי שגיאה והרשאות ספק מצומצמות עברו. אין פרסום פוסט או שליחת הודעה חברתית.

תוכנית חזרה: להסיר רק את הכתובת המדויקת שנוספה, להסיר את הפעלת OAuth ב־build הפריוויו, ולבדוק שהאתר החי שומר את כתובות החזרה שלו.

החיבור הזמין של Supabase כולל SQL ו־Edge אך אינו חושף קריאה/עדכון של הגדרות Auth. אין לעקוף זאת באמצעות SQL פנימי או משיכת מפתח. נדרשת פעולה זו בדשבורד המאומת או חיבור ניהול שמאפשר את הגדרת Auth; לא נדרש למסור סיסמה/מפתח בצ׳אט.
