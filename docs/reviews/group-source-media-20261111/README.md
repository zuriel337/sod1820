## 3. המסלול של הודעה

1. **קליטה (Edge):** תמונה או וידאו רגילים (`imageMessage` / `videoMessage`) שנכנסים לקבוצת מקור. לא תגובה עם קובץ, לא מסמך ולא אודיו.
   - נשמרים קודם **פרטית** ב־`submission-inbox`, כמו היום.
   - השורה נכנסת עם `group_source_intake_public = true` ו־`image_url = storage-object:<id>`. זה כמו טקסט, רק עם מקור פרטי.
2. **הוכחה (SQL):** `record_channel_update_group_media_proof_v1` מפעיל את כלל הזהות של v1 (בלוק הזהות הועתק תו בתו).
   - הזהות: מזהה השולח מתאים למספר אחד של תורם, או לחיבור וואטסאפ מאומת אחד.
   - בדיקות נוספות: המקור הפרטי קיים בדלי הפרטי ומסוג ההודעה.
   - נרשמת שורת הוכחה `text_only = false`, `media_kind = image|video`.
   - מוחזר `publishable` מתוך הכלל היחיד `group_source_media_publishable_v1`.
3. **עותק ציבורי (Edge):** רק אם השרת ענה `publishable = true`. אותם בייטים נכתבים פעם אחת לנתיב 2029 היציב של ההודעה: `media/sod1820/2029/<kind>/YYYY/MM/<UUID v5>/original.<ext>`, עם `upsert:false`.
4. **רישום (SQL):** `record_group_source_public_media_v1` בודק מחדש את הכלל, את הנתיב המדויק (אותו UUID v5 ואותו חודש), ואת זהות הסוג והגודל מול המקור הפרטי. רק אז נרשמת שורה ב־`group_source_public_media`.
5. **קריאה (SQL):** אותו קורא, אותו שם וארגומנטים, ועוד שלוש עמודות (`media_kind`, `media_url`, `thumb_url`).
   - שורות טקסט חוזרות בדיוק כמו היום.
   - שורת מדיה חוזרת רק עם עותק רשום שעדיין קיים ב־Storage, ורק כשהכלל מתקיים ברגע הקריאה.
   - הכיתוב עובר את אותו צנזור.
   - מציין המקום („📷 עדכון” / „🎬 עדכון וידאו”) הופך לגוף ריק.
   - ל־`thumb_url` של וידאו נכנס ה־poster כשהוא קיים.
6. **אתר 2029:** אין שינוי קוד. `groupRowToWorldUpdate` ו־«עכשיו» כבר קוראים `media_kind`/`media_url`/`thumb_url`, מאמתים שהכתובת היא Storage הציבורי של הפרויקט, ומציגים תצוגה מקדימה לתמונה או לסרטון. רק הערות תיעוד עודכנו.
