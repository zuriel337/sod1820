## הממצא והתיקון

קובץ העיצוב של IBM Plex Mono מ־Google Fonts נטען כ־stylesheet חוסם ב־2029.html. בהשהיה מבוקרת של הבקשה, מודול האתחול לא הגיע אפילו לרישום ה־SW ולא התחילה בקשת פוסטים. שחרור הבקשה לאחר שבע שניות הפעיל את אותו אתר. כך הוכח מסלול תקיעה ברמת תלות הקוד במשאב רשת משני; אין צורך בשינוי מסד, שרת, הרשאות או מטמון מידע כדי לתקנו.

התיקון היחיד בקוד המוצר משנה את טעינת אותו גופן לטעינה שאינה חוסמת: `media=print`, החלה ל־all באירוע load ו־noscript תואם. המשפחה והמשקלים, הגופנים המקומיים, התוכן, העיצוב, הסדרות, הדירוגים, הגרף והתפריטים לא השתנו. לא נוסף loader או מנגנון מטמון. App2029, main2029, Frame, הקוראים, ה־worker, Preview API ושער Production ללא דלתא. כלי האבחון והתיעוד נפרדים מהשינוי במוצר.

**הכשל ההיסטורי בן 60 השניות נשמר.** בלי trace מקורי אי אפשר לקבוע בוודאות שדווקא אותו קובץ גופן גרם לו. התיקון נתמך בשחזור חיובי ובבדיקת מניעה; [כל התקיעות והכשלים](FAILURES.md) כוללים גם שגיאות כלי בדיקה, ציפיית תפריט שגויה וחסימת גישת Vercel. הם לא הוסבו בדיעבד לירוק.

## מה נבדק

- **הגנות:** קובץ ה־worker החי זהה בבייטים בשני הפריוויו: `c3436d48371f517874c76d0396fe1c973a625c85845b7d33a6636001fb82c871`. בכל 28 הריצות קריאות המידע התחילו לאחר שליטת SW. ברענון ובפתיחה מחדש נבדק initialController=true. אין עקיפה, unregister או cache bypass במסלול Native. בדיקה בודדת ללא grant הגיעה לדף כניסת Vercel; עם grant מורשה התקבלו מסמך וזהות מה־origin הנכון. הגנת Vercel לא שונתה.
