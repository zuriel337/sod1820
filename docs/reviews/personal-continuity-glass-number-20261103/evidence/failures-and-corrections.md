# כשלים שנשמרו בסבב

- סביבת הבדיקה הראשונית שכתבה בקשות Auth לכתובת fixture בחלון הדפדפן, ולכן ה־worker דחה אותן. ניסוי נוסף העביר גוף stream בין כתובות והוביל לחריגה באותו מתאם. תוקן רק מתאם הרשת המבודד: קוד admission מה־build נשאר זהה. אין ראיה מכך לכשל סיסמה בשרת האמיתי.
- סלקטור הספרייה הראשוני כלל כותרת בלבד, בעוד שם הכפתור כולל סוג; בהרצה חוזרת הופיע אותו שם גם בהיסטוריה. הבדיקה כעת ממוקדת במדור שמורים, בלי להסתיר כפילויות בתוך המדור.
- רענון פרופיל אחרי אישור שמירה מחק את הודעת האישור. זה כשל ממשק אמיתי שתוקן; אותו חשבון שומר את האישור, ושינוי זהות מאפס את העורך.
- אחרי רענון, פעולות הקשר מקומיות יכולות להשאיר syncStatus=pending גם כשהפריט נמצא בספרייה. מצב חברות ברשימת השמורים מוצג בנפרד מאישור שמירה מהשרת; הודעת הצלחה חדשה עדיין מחייבת receipt.
- כפתור השמירה בפוסט נמצא בתוך ״פרטי הפוסט״ הקיים. הבדיקה פותחת אותו לפני פעולה, ואינה עוקפת visibility.

הבדיקות הסופיות כוללות כשל כתיבת פנקס, שמירת הטקסט ואי־הצגת הצלחה, ניסיון חוזר מפורש, רענון והפרדת שני חשבונות מלאכותיים. אין קבלת חשבון אמיתי.

- לאחר חיבור כינויי הכניסה האישיים, בדיקת artifact ישנה ציפתה ל־200 בדף /2029/me. היא הותאמה ל־308 ואז יעד חשבון200/noindex; אין הסרת תנאי פרטיות. בדיקה מורחבת גילתה גם index שגוי לכינוי accountבמצב תוצר רדום, ותוקן המימוש: accountתמיד generic/noindex. Fragmentנבדק בדפדפן משום שאינו נשלח ב־HTTP.
