## מה כבר בסדר
הטוקנים והפלטה הם מקור אחד (`paletteTokens2029.js` → `--s29-*`), ואין `prefers-color-scheme` מקביל. משפחת הכפתורים ומשפחת הבחירה כעת בתשתית ונאכפות. הסוכן שכותב כפתור בלי `.r29-btn` נכשל ב־CI.

## הפערים הגדולים, לפי השפעה
1. **טפסים (9)** ו**חלוניות (5)**: אין מקור קנוני; כל סוכן ממציא אחד. תיקון = תוספת קטנה בשכבת ה־Royal הקיימת (`.r29-field`, `.r29-sheet`), לא ספרייה, ובעקבות סעיף בחוזה V2.
2. **צבעים וטיפוגרפיה (2, 3)**: מקור אחד קיים אבל לא נאכף: 770 hex, 1,562 px.
3. **מדיה (11) ואייקונים (4)**: רכיב קנוני קיים, השימוש בו אינו מחויב.
4. **מרווחים (8)**: אין סולם בכלל; ההחלטה הראשונה היא סולם מצומצם של טוקנים, באישור.

## המלצה לאכיפה אוטומטית ב־CI (אחת, ללא מערכת חדשה)
להרחיב את הכלי שכבר נוסף, `scripts/lib/buttonFamilyScan2029.mjs` + `scripts/button-family-baseline-2029.json`, לבדיקת **מנוף חד־כיווני אחת** לכל המשפחות, בקובץ בסיס אחד:
- כל משפחה = כלל סריקה קצר (regex) ומונה לקובץ: ליטרלי hex/rgba מחוץ ל־`paletteTokens` ול־`royal2029.css` (3); `font-size:Npx` (2); `<svg` inline מחוץ ל־`NavigationIcon2029`/`ProviderMark2029` (4); `role="dialog"`/`position:fixed` מחוץ לרכיב הגיליון הקנוני (5); `<img` גולמי מחוץ ל־`CanonicalMediaFigure2029` (11); כללי `input/textarea` מחוץ למשפחת הטפסים (9); `margin/padding` ב־px (8).
- הסדר: ראשית אזהרה (דוח בלבד), אחר כך מנוף על קבצים חדשים, ובסוף על קבצים קיימים. כל מעבר שלב — החלטת ZURIEL.
- **ברירת מחדל לסוכנים:** (א) `Sod2029Shell` מוסיף `.r29` כהיקף ברירת המחדל של אזור התוכן, כך שרכיב חדש מקבל את השפה בלי לבחור (שינוי קטן בבעלות המסגרת, בכפוף לתקציב המעטפת); (ב) סעיף אחד ב־`CLAUDE.md` שמפנה למפה הזו ולבדיקה (פוינטר, לא העתק חוק); (ג) הבדיקה נכשלת עם הודעה שמצביעה על הרכיב הקנוני.
- **שינוי מרכזי אחד מתעדכן בכל הצרכנים:** רק אחרי שהצרכנים עברו ל־`.r29-*` (איחוד הדרגתי: ראו `docs/reviews/button-family-20261125/README.md`). עד אז הטוקנים בלבד משתנים מרכזית.
