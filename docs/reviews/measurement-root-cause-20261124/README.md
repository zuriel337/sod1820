## 6. החבילה: תיקון `fn_human_entrances` (ממתין לאישור)

**קבצים:**
- `supabase/proposed/20261124210000_human_entrances_v2_source_PROPOSAL.sql`
- `…_ROLLBACK.sql`
- `…_ACCEPTANCE.sql`
- `tests/human-entrances-v2-source-20261124/{fixture.sql, realpg.sh}`

**מה משתנה (מימוש בלבד, בלי שינוי חוזה ובלי נגיעה ב־`ingest_event`, ולכן בלי תלות בסדר מול #1545):**
1. `source = coalesce(events.via, arrival/source של הסשן)`. זה אותו ערך של `via()` בדפדפן, דרך הנשא של v2.
2. כלל v2 (‏direct + בלי מדינה) מוחל רק כשמדינה נאספה, כלומר בנחיתה שאינה v2. ב־v2 אין מה להעריך, ולא ממציאים ראיה.
3. כלל v3 (‏direct + דף מספר + צפייה אחת) בלי שינוי.
4. `suspected_bot` אף פעם אינו NULL, ולכן גולמי = נטו + חשוד.
5. `traffic_daily` מחושב מחדש מ־15.11 עד היום. השורות הקודמות נשמרות קודם ב־`analytics_cache`, בטבלה קיימת.

**שמירות:**
- md5 של שתי הפונקציות החיות.
- הפלט שלפני 15.11 חייב לצאת זהה לגמרי, אחרת הטרנזקציה נעצרת.
- אחרי ההחלה: אין NULL, והשוויון נשמר בכל יום.

**הוכחה לפני האישור:**
- **סימולציה חיה (קריאה בלבד):** ב־65,989 סשנים בין 8.7 ל־14.11 לא השתנה כלום: אפס שינויים ב־`suspected_bot`, ב־`source` ובנימוק. ב־15–24.11 נפתרו 1,350 ערכי NULL. 90 סשנים סומנו חשודים לפי כלל v3, ו־30 סשנים בלי arrival נשארו בלי מקור.
- **`realpg.sh` על PostgreSQL 16 מקומי: ‏23 מתוך 23 עברו.** הבדיקה מאמתת:
  - שתי הפונקציות בקובץ ה־fixture זהות בבית לחיות;
  - המצב החי משוחזר;
  - אחרי התיקון יום Legacy לא משתנה, ויום v2 מתוקן;
