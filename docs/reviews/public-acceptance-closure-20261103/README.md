## דיווח — ממצאים והצעה מדויקת, טרם הופעלה

שלוש חסימות מקומיות כיום: guard בטופס, `track/emit` שמבצעים return בפרופיל הקריאה, ו־SW שחוסם את כתיבות המקור. אין תלות הכרחית בשינויי הדיוור הממתינים.

- רעיון ופנייה כללית משתמשים כבר ב־`sendContactMessage` → INSERT ל־`contact_messages`, ומחכים לתוצאת השרת. RLS חי מגביל שם 1–100, אימייל 3–200 והודעה 1–3000; SELECT למנהל בלבד. אין trigger בטבלה. **שמירת פנייה אינה שליחת מייל או הרשמה.**
- תקלה משתמשת ב־IssueReport → track → visitor_events + events/ingest_event. הפליטה הקיימת fire-and-forget, ולכן אינה מספקת אישור שמירה. הסרת guard בלבד תיצור שוב הצלחה מדומה.
- נבדק המקור החי של `ingest_event`: קבלת `p_is_bot=false` מבצעת INSERT ל־events. `p_sod_id=null` גורם ל־resolve_person לחזור לפני כל כתיבת זהות. אין trigger בטבלת events. אפשר לשמור דיווח מפורש באותה תשתית בלי לפתוח כניסה/שיווק/קרדיטים/דיוור או ליצור זהות חדשה.

[הצעת patch מדויקת](report-activation.proposal.patch) — **לא הוחלה**:

1. IssueReport ממתין ל־RPC הקנוני עם surface/event_type קבועים, מזהה מבקר null, הקשר מסונן וטקסט עד 500 תווים. רק אישור שרת מציג הצלחה. כשל/ניתוק לא מציגים הצלחה ולא מפעילים ניסיון אוטומטי; תוצאת timeout יכולה להיות לא ידועה.
2. פנייה/רעיון שומרים בטבלת contact_messages הקיימת. צורת array של Supabase נבדקת במפורש.
3. ה־SW מאשר רק שתי צורות בקשה מדויקות, עם גבולות שדות וגודל; שום טלמטריה כללית אינה נפתחת.
4. Legacy ממשיך במסלול הרגיל. אין SQL/מיגרציה/Edge/Auth/mail deployment או טבלה/חנות דיווח מקבילה. Detector הקיים ממשיך לקרוא issue_report מתוך events. דיווחי הפריוויו יהיו נתונים אמיתיים בפרויקט הראשי, ויוכלו להיצרך בידי מנגנוני התפעול הקיימים.

בדיקות ההצעה: **3 עברו**, כולל await לאישור, כשל ללא הצלחה/ניסיון חוזר, null לזהות, שלילת spoof/event אחר/PII/טקסט ארוך ושמירת פנייה. אלו בדיקות סינתטיות; לא נשלח דיווח חי. ה־patch עובר git apply --check. לפני הפעלה נדרשים עוד מבחן רכיב/transport משולב ובדיקת שמירה חיה מוגבלת בהיתר; אין טענה שההצעה כבר התקבלה מקצה לקצה. rate/abuse של השרת הקיים אינו מתחזק משומר דפדפן, ונשאר חלק מ־S2.

**בקשת אישור ממוקדת:** להפעיל רק שמירת דיווח מפורש ופנייה לפי ה־patch בפריוויו ולבצע דיווח בדיקה אחד מסומן לכל מסלול. אלו כתיבות לנתונים חיים; אין מחיקה אוטומטית. שינויי b21ed1ff, דיוור והתחברות חברתית נשארים בהמתנה. חזרה: ביטול פריסת הפריוויו לגרסה הנוכחית מחזיר את חסימת השליחה; הרשומות שנשמרו אינן נמחקות.
