## Implemented

- Explicit ELS entry adds the normalized phrase and scope to its existing exact
  replay context. The shared adapter remains text-private by default. Merely
  opening a page, selecting an occurrence or opening Raziel never submits AI.
- Ordinary explicit questions carry `surface_semantic.els.grounding =
  canonical_replay_v1`. The existing handler verifies the axis through the same
  `els-search-bridge / verify_batch`. Phrase, scope, corpus, start, skip and
  direction are authoritative only after that replay. End comes from the
  replay response, not a client field or model arithmetic. No fabricated grid.
- Follow-up adds only the UUID of a completed, same-occurrence reading. The
  existing private-job repository checks the authenticated owner, complete/live
  result, snapshot, full axis/corpus identity and verification receipts. Only
  bounded verified findings are projected; plain source text is labeled
  separately. No raw matrix, model notes or provider reasoning is reintroduced.
- The handler replaces model-authored fact rows with the replayed occurrence
  and the server's verified reading findings. The model still supplies the
  explanation, not the verification. It cannot initiate a scan from this path.
  The existing source-name field identifies the canonical engine's letter/location
  verification, with an explicit explanation limit; it does not call the answer
  unsourced or attest that the model's interpretation is verified.
- The transport requires a matching server receipt. An old server that ignores
  this context cannot silently return an apparently grounded answer.
- Same-axis job reference survives transcript trimming and the existing saved
  snapshot serialization. Different term, scope, corpus, start, skip or direction
  cannot inherit a previous reading. A stale open companion fails closed when
  Research Context selects another occurrence.
