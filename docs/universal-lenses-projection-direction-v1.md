# SOD1820 — Universal Lenses Projection Direction v1

**Date:** 2026-09-04  
**Status:** APPROVED PRODUCT / NAVIGATION DIRECTION — ZURIEL Human Gate  
**Scope:** Projection direction only. No schema, table, engine, graph, store, canonical promotion, publication, route, merge or deploy is authorized by this document.

## 1. Direction

SOD1820 is one Research / Knowledge OS over one Reality Graph and one Human Gate.

The future system must let the same knowledge be entered and viewed through many lenses without duplicating truth:

- Number
- Topic / Convergence
- Time / Chronology / Year
- Journey / Research Path
- Source / Book
- Person / Name
- Verse
- Event
- ELS
- Representation / Language
- Depth / Spatial projection

A lens is a projection over existing identity, findings, relations, provenance and governance. A lens is never a second truth store.

**Foundation → Projection → Experience.**

The current site and current Number/Topic/Journey/Timeline surfaces are Transitional / Legacy Surfaces. They preserve capability and provenance but do not dictate the target architecture.

## 2. Entity-first, not page-first

The guiding question is:

> What does SOD1820 know about this thing, and how can the researcher continue from here?

A Number Hub is therefore not a separate Number Research OS. It is the first rich Golden Case of a future Entity-oriented projection contract.

The same underlying model must be able to serve Number, Topic, Person, Name, Verse, Source, Event and future ELS-derived entry points.

## 3. One entity, many lenses

For an entity such as Number 1237, the future projection should be able to expose the same underlying state through lenses such as:

- Knowledge / verified graph state
- Current research and Research Objects
- Relations and ranked connections
- Topics
- Sources
- Chronology
- Journeys / paths
- Human-Gate state
- History / provenance
- Access / available depth

Changing lens must not copy or rewrite the underlying truth.

## 4. Chronology is a projection

Time must be first-class enough to support chronological research without creating a second Timeline truth system.

For an entity such as 1237, a chronological lens should eventually be able to show how the entity appeared across historical posts, gallery material, events, sources and later research.

The projection must preserve distinct temporal meanings when available:

- event / occurrence time
- source / publication time
- extraction time
- research / discovery time
- Human-Gate decision time

These times are not interchangeable.

Existing temporal and Timeline primitives are to be reused and extended. No parallel Time graph/store is authorized here.

## 5. Journey / Path — cross-lens requirement

A durable Journey or Research Path must not belong to one page.

When a path has valid identity and governance, it should be re-enterable from every relevant participant or lens — for example from a Number Hub, Topic Hub, Search, Research Workspace, Source, Person, or future ELS lens — without copying the path's truth into each surface.

A Journey may contain or traverse entities, findings, relations, topics and sources, but Journey existence does not make any step true, canonical or published.

### Existing journey concepts must remain distinct

The system already contains multiple concepts using Journey terminology. They must not be merged merely by name:

1. **Number Knowledge Journey** — e.g. the live approved `fn_number_journey(1237)` projection.
2. **User / Workspace Journey** — personal research continuity/history in the existing ResearchProvider/user research system.
3. **Research / Discovery Path** — a possibly branchable ordered research path through findings/entities/relations.

The exact identity contract for a reusable Research / Discovery Path remains under the dedicated Claude Foundation/Projection challenge. No new Journey table/store/system may be created unless that challenge proves an existing-primitives solution is insufficient and ZURIEL approves the resulting Foundation decision.

## 6. 1237 Golden Case

Number 1237 is the first stress test because it already spans old and new layers:

- an existing Number node in the Reality Graph
- graph relations to entities, posts, images, topics, numbers and zero-scale values
- an existing approved Number Journey with multiple branches
- historical source/post/gallery material
- new Research Objects and engine-verified findings
- Human-Gate and privacy distinctions
- prior Human decisions that must not disappear

The Golden Case must show these layers together while preserving their different identities and truth/governance states.

The current research sequence:

`112 → 358 → 676 → 1120 → 1237 → 2137`

is a **research stress test / candidate path only**. It is not declared canonical, published, or a durable Journey by this document. If it later receives valid Journey identity and Human-Gate approval, it should be re-enterable from all participating entities and related Topics without duplicating truth.

## 7. Topic Universe

The future system may contain thousands of Topics.

Topics must remain first-class graph/research entry points and support scalable browse/search/filter/rank/pagination using existing canonical primitives wherever possible.

Important distinction:

- curated / Human-reviewed Topic/Convergence
- raw engine-detected convergence

These are different truth/governance layers and must never be collapsed because they share terminology.

A Topic Hub such as `התגלות` should eventually be able to expose related Numbers, Findings, Sources, Journeys, People/Events and future ELS findings through the same universal projection model.

## 8. Facets and filters

Future filtering is a Projection concern unless a real missing Foundation semantic is proven.

Expected facets include, where supported by canonical data:

- entity type
- topic
- number
- source type
- time/year
- person
- method / engine
- verification
- research status
- canonical status
- publication status
- privacy / access
- relation strength
- provenance
- depth
- language / representation
- journey membership

**Rank, don't hide.**

The system should not load the entire tree at once. Bounded queries, ranking, pagination, lazy sections and progressive disclosure belong to the Projection/Experience implementation.

## 9. Depth / subscription / access

Subscription or entitlement may control access, tooling, amount of depth, compute, saved work or available lenses.

It must never change truth.

- Paid ≠ true
- Private ≠ paid
- Canonical ≠ published
- Approved ≠ canonical
- Depth ≠ truth

Existing access/privacy/truth axes remain separate.

## 10. Search as entry into the same universe

Future search should resolve to the same entity/topic/path identities rather than create a separate flat-results truth system.

Examples:

- Search `1237` → Number entity projection
- Search `התגלות` → Topic/entity projection
- Search a person → Person projection
- Search a source/book → Source projection
- Search a valid independently addressable Journey → Journey/Path projection

Each entry point continues into the same graph/research state and can switch lenses without losing context.

## 11. Build direction

Subject to the current Claude Universal Entity · Topic · Journey Foundation/Projection challenge, the intended Projection sequence is:

1. Confirm reusable Universal Entity Projection contract from existing primitives.
2. Build Number 1237 as the first Golden Case.
3. Validate the same contract with a small Topic case such as `התגלות`.
4. Resolve Journey/Path identity only if the challenge shows that existing primitives cannot safely represent it.
5. Add faceted tree/search/chronological navigation progressively.
6. Add richer Experience, depth, premium and spatial renderers only above the shared state.

This sequence is a direction, not a release authorization.

## 12. Non-negotiable constraints

Do not create:

- a second Reality Graph
- a Number-specific Research OS
- a second Topic system
- a second Workspace
- a second Human Gate
- a second Journey store merely because different surfaces use the word Journey
- a Timeline truth store separate from existing entities/findings/sources
- truth semantics tied to subscription level

Reuse and extend existing primitives first.
