# ניסוי מבודד: זיהוי ממצאים במטריצת ELS

**סטטוס:** ניסוי מבודד, לקריאה בלבד. לא משנה `src/`, לא כותב ל-DB, לא פורס, לא יוצר מנוע / Provider / שיחה / מסלול AI חדש.
**בעלים סמנטי של המנוע:** `els_research_layer_law:v9`. **המנוע היחיד:** `public.els_search_geometry_core_v1` (עם `els_search_page_core_v1` לאיתור העוגן).
החיפוש הקלאסי לא נגוע. נעילת Production של Legacy לא נגועה.

## על בסיס הקוד הקיים

- **מנוע:** `public.els_search_geometry_core_v1` (גיאומטריית מטריצה: `axis_width`, אזור, מערך דילוגים, תקרה 4,000 מופעים) ו-`els_search_page_core_v1` לאיתור העוגן. שום מופע לא נוצר מחוץ להם.
- **סטטיסטיקה:** `src/lib/research/els2029StatisticalControls.js` (`benjaminiHochberg`, `applySignificanceLabels`) — מיובא, לא משוכפל.
- **גיאומטריה:** טבלת שמונת הכיוונים, מיפוי תאים וכלל ה-wrap נבדקים בטסט מול `src/lib/research/els2029VectorGeometry.js` (`deriveElsLineGeometry`): אותו צעד `(dr, dc)`, אותם תאים, ואותו כלל גלישה.
- **לא בשימוש בכוונה:** `els2029AdaptiveScanner.js` / `elsAutomaticResearchPlan.js` מתזמרים קריאות עמוד מוגבלות מהדפדפן עבור ביטויים שהמשתמש הזין; סריקת מילון על אזור דורשת את ליבת הגיאומטריה ואצוות בצד השרת.

## מה הניסוי עושה

1. **סורק אזור מטריצה מוגדר בכל שמונת הכיוונים** מול מילון הפרויקט (`public.gematria_words`, מילים בודדות), ומחזיר מילים ומיקומים שאפשר לסמן על המטריצה.
2. **נותן ל-Claude לקבץ** את הממצאים סביב נושא המחקר, בלי יכולת להמציא אות, מילה או מיקום (חבילה דטרמיניסטית + מאמת).
3. **משווה לאזורים אחרים** — כאפשרות נפרדת (`--controls on`), עם שיטת חישוב מוצהרת (`node run.mjs method`).
4. **בדיקת אמת (probe)** — אותה קריאת מנוע למילים מפורשות, כדי להבדיל "הסריקה לא כיסתה" מ"המילה לא באזור".
5. **מודד** זמן, מספר ממצאים ומה הושמט בגלל מגבלות הסריקה.

אין שום קוד פרטי לצופן מסוים: דוגמאות הן נתונים (`examples.json`: מונח עוגן + דילוג), וטסט (`no example-specific code…`) נכשל אם הספרייה מזכירה מילת עוגן/יעד או עוברת על הזרם בעצמה.

## איך שמונת הכיוונים נגזרים (בלי חשבון ELS)

מטריצה ברוחב `W` שומרת את הזרם בשורות של `W` אותיות. רצף רציף על המטריצה הוא בדיוק מופע של המנוע עם דילוג:

| דילוג במנוע | כיוון על המטריצה | הערה |
|---|---|---|
| `1` (±) | שורה | טקסט רגיל של התורה, **לא ELS**; מסומן `plain_text_row` |
| `W` (±) | עמודה למטה / למעלה | ELS |
| `W+1` (±) | אלכסון מטה בכיוון הקריאה / מעלה נגד כיוון הקריאה | ELS |
| `W−1` (±) | אלכסון מטה נגד כיוון הקריאה / מעלה בכיוון הקריאה | ELS |

- קריאה אחת למנוע לכל מילה לכל קבוצת כיוונים, על **כל** המטריצה (`cd` = שלושת הדילוגים `W−1, W, W+1`; `row` = דילוג 1). אין קריאה לפי אזור: המנוע עובר על כל הזרם בכל מקרה, כך שהקטנת האזור לא חוסכת עלות.
- מופע שחוצה גבול שורה (עמודה "נגללת" לשורה אחרת) נפסל: `col(start) + (len−1)·dCol = col(end)` ובתוך `[0, W−1]`.
- ממצאי האזור, ספירות האריחים וסכומי המילים נגזרים **רק מסינון המופעים שהמנוע החזיר** (ספרים, לא מחשבים).
- מיקומי המנוע הם 0-based; `torah_stream.idx` הוא 1-based (האות במקום `p` היא `idx = p+1`) — טסט מכסה.
- הכיוונים נקראים לפי **כיוון הקריאה**: עמודה 1 היא האות הראשונה בשורת הטקסט (הצד הימני בתצוגה עברית), `fwd` = לעמודות עולות.

## הרצה

הכלי לא מתחבר ל-DB. הוא **בונה SQL לקריאה בלבד** (`SELECT` בלבד, ערכים מאומתים) ו**מנתח את ה-JSON** שחזר; מי שמחזיק גישה מריץ את ה-SQL (כאן: Supabase MCP, פרויקט `linswmnnkjxvweumprav`).

```
node experiments/els-matrix-scan/run.mjs sql --kind total                       # אורך הזרם
node experiments/els-matrix-scan/run.mjs sql --kind count                       # כמה מילים לכל אורך במילון
node experiments/els-matrix-scan/run.mjs sql --kind anchor --example columbia    # מיקום העוגן דרך המנוע הקנוני
node experiments/els-matrix-scan/run.mjs init --example columbia --anchor anchor.json --total-letters N --dict counts.json --out state.json
node experiments/els-matrix-scan/run.mjs sql --kind batch --state state.json --offset 0 --limit 90 --directions both [--controls on]
node experiments/els-matrix-scan/run.mjs sql --kind letters --state state.json   # אותיות האזור (תצוגה ואימות)
node experiments/els-matrix-scan/run.mjs sql --kind probe --state state.json --words a,b,c
node experiments/els-matrix-scan/run.mjs report --state state.json --batches DIR [--probe probe.json] [--membership present.json] [--controls on]
node experiments/els-matrix-scan/run.mjs markup --state state.json --batches DIR --letters letters.json [--probe probe.json] --out-json marks.json --out-html matrix.html
node experiments/els-matrix-scan/run.mjs packet --state state.json --batches DIR   # חבילת הקיבוץ למודל
node experiments/els-matrix-scan/run.mjs validate --state state.json --batches DIR --answer answer.json
node experiments/els-matrix-scan/run.mjs method                                  # שיטת ההשוואה לאזורים אחרים, במדויק
node --test experiments/els-matrix-scan/test/els-matrix-scan.test.mjs
```

האזור: `21 שורות × 61 עמודות`, ממורכז על האמצע של מופע העוגן וחסום בתוך המטריצה. המילון: מילים בודדות, אורך `[minLen, maxLen]`, ממוינות מהארוכה לקצרה ואז אלפביתית, ונחתכות ב-`offset/limit` כדי לפצל לאצוות ולתקצב.

## פלט: מה אפשר לסמן

`markup` כותב `marks.json` (תאים מקומיים 0-based עם האות בכל תא + היסט למטריצה הגלובלית) ודף `matrix.html` סטטי, RTL, בלי סקריפטים ובלי משאבים חיצוניים. לפני הכתיבה, כל ממצא נקרא מחדש **מהאותיות האמיתיות של הזרם** ומשווה למילה שלו (אותיות סופיות מנורמלות): מיקומי המנוע ↔ תאי המטריצה ↔ אותיות חייבים להתאים, אחרת הפקודה נכשלת.

## קיבוץ על ידי Claude בלי להמציא

`packet` בונה טקסט עברי דטרמיניסטי: מזהי ממצאים (`F001…`), מילת המנוע, כיוון, מיקום מקומי ומספר המופעים במטריצה כולה. **מילות הערכה לא נכנסות לחבילה** (טסט). המודל צריך לענות ב-JSON בלבד:

```
{"groups":[{"label":"…","finding_ids":["F001"],"why":"…"}],"ungrouped_ids":["F002"]}
```

`validate` דוחה: מזהה לא מוכר, מזהה בשתי קבוצות, ספרות בטקסט, מילה מצוטטת שאינה ממצא מנוע, מפתח שאינו בסכמה (למשל `cells`/`positions`), ו-JSON לא תקין. **שום מודל לא נקרא מהספרייה ואין מסלול AI חדש**: החבילה נועדה לשיחה/פונקציה הקיימת, והמאמת בודק מה שחוזר.

## השוואה לאזורים אחרים (אפשרות נפרדת, כבויה כברירת מחדל)

`sql --kind batch --controls on` מוסיף ספירה לפי אריחים מאותם מופעים שכבר חזרו (**אפס קריאות מנוע נוספות**); `report --controls on` מפיק את ההשוואה. בלי הדגל — אין ספירת אריחים ואין p-value. השיטה, כפי ש-`run.mjs method` מדפיס:

1. רוחב המטריצה `W` מוצהר; אזור היעד = שורות `r0..r1` × עמודות `c0..c0+cols−1`.
2. אריחים באותו גודל, עם עוגן באזור היעד, מכסים את המטריצה; רק אריחים שנכנסים כולם בתוכה (אריחי שוליים חלקיים נופלים).
3. בכל אריח סופרים מופעי מילון **שנמצאים כולם בתוכו** ולא נגללים בין שורות.
4. אריח היעד (0,0) מוחרג. `extreme` = מספר אריחי הבקרה שבהם הספירה ≥ זו של היעד; `n` = מספר אריחי הבקרה.
5. `p = (extreme + 1) / (n + 1)` (add-one, אף פעם לא 0 — אותה אמנה כמו `runSeededControls`).
6. תיקון משפחה: כל הסטטיסטיקות המדווחות הן משפחה אחת מוצהרת (`els_tile_translation_family_v1`), מתוקנת ב-Benjamini–Hochberg דרך `benjaminiHochberg`/`applySignificanceLabels` הקיימים ב-`src/lib/research/els2029StatisticalControls.js`. התווית היא `NOT_SIGNIFICANT_UNDER_DECLARED_NULL` או `FDR_SURVIVES_DECLARED_NULL` — לעולם לא "משמעותי".
7. **מגבלות:** אריחים שכנים באותו טקסט ולכן **לא בלתי תלויים**; גודל האזור והמילון נקבעים מראש אבל בחירת היעד היא **post-hoc**; הצפיפות במילון **אינה** קוהרנטיות סמנטית. ה-p עונה רק על "האם האזור צפוף במילים של המילון יחסית למקומות אחרים באותה מטריצה", לעולם לא על "האם זה משמעותי".

## בדיקת אמת (probe) והערכה

`evaluationWords` ב-`examples.json` משמשות **רק אחרי הריצה**, כדי למדוד recall, ולעולם לא נכנסות לחבילת המודל. `report --probe` שולח את המילים האלה לאותה קריאת מנוע ומחזיר פסק דין לכל מילה:

| פסק דין | משמעות |
|---|---|
| `FOUND_BY_DICTIONARY_SCAN` | הסריקה דיווחה עליה |
| `PRESENT_IN_REGION_BUT_MISSED:<סיבות>` | קיימת באזור (ELS) אבל הסריקה לא דיווחה: `NOT_FULLY_SCANNED_LENGTH` (האורך לא נסרק), `NOT_IN_DICTIONARY`, או שניהם |
| `ONLY_AS_PLAIN_TEXT_IN_REGION` | מופיעה באזור רק כטקסט רגיל (שורה) |
| `ABSENT_FROM_REGION` | לא באזור, בלי שהפלט נחתך |
| `NOT_SEEN_BUT_ENGINE_OUTPUT_TRUNCATED` | לא נראתה, אבל קריאת המנוע נחתכה (תקרת 4,000) — הספירה חסרה |

### קולומביה (`קולומביה`, דילוג 4545, אזור 21×61, שורות 47–67, עמודות 3306–3366)

- סריקת מילון (5–9 אותיות, 1,908 מילים): **11 ממצאים** — 3 ELS (`בעיות` ↙, `התחלה` ↖, `יכולה` ↗) ו-8 מילים בטקסט רגיל (`נתניהו`, `שבעתים`, `אלהיך`×6; "נתניהו" הוא פשוט "נתן יהוה"). כולם נקראו מחדש מאותיות הזרם והתאימו (11/11).
- השוואה לאזורים אחרים: ב-221 אריחי בקרה ממוצע **6.40** ממצאי מילון לאריח (מקסימום 15), באזור היעד **3**; `extreme=208`, `p = q = 0.941` → `NOT_SIGNIFICANT_UNDER_DECLARED_NULL`. צפיפות המילון באזור **אינה** חריגה.
- קיבוץ: החבילה (`results/columbia/packet.txt`) נמסרה בלי מילות היעד; הקיבוץ שנבדק מצא קשר חלש יחיד (`בעיות`) והשאיר את כל השאר בלי קבוצה; המאמת קיבל אותו ודחה קיבוץ מזויף (4 שגיאות). ראו מגבלות: זו **לא** ריצת מודל עיוורת.
- **בדיקת אמת — מה שבאמת באזור:** `ספינת` (ELS, אלכסון `W−1`, תאים (8,36)→(12,32)) ו-`יכלאש` (ELS, אלכסון `W+1`, תאים (8,26)→(12,30)) קיימות באזור והן **תמונת מראה סביב עמודת קולומביה** (עמודה 31): 26↔36 ו-30↔32 באותן שורות. `יכל` ×2 ELS (אחת היא תחילת `יכלאש`), `נפל` ELS ×1 (+4 בטקסט רגיל), `אש` ×7 ELS (+16 בטקסט; קריאת ה-cd נחתכה בתקרת 4,000).
- **למה הסריקה פספסה:** `ספינת` ו-`יכל` **אינן במילון** (`ספינה` ו-`אש` ו-`נפל` כן); `יכלאש` אינה מילה אלא צירוף; `יכל`/`אש`/`נפל` קצרות מטווח האורכים שנסרק.
- **רעש של מילים קצרות (דגימה):** 60 מילים בנות 3 אותיות נתנו **111** ממצאים באזור לעומת ממוצע **109.8** באריח בקרה (`p = 0.39`): בערך 1.85 ממצאי מקרה למילה, כלומר כ-2,000 לכל 1,091 המילים בנות 3 האותיות. סריקה כזו לא ניתנת לקיבוץ בלי קריטריון מבני.

## מה הושמט / פערים (מוצהר, לא מוסתר)

- **אורכים קצרים לא נסרקו**: בקולומביה 2–4 אותיות (2,965 מילים), בצביר עשירי 2–5 אותיות (4,227 מילים). סיבה: עלות (≈ 0.2–0.3 ש' למילה) ורעש (ראו דגימה). מילים בנות 2 אותיות נחתכות בתקרת המנוע (4,000 מופעים לקריאה).
- **שורות (דילוג 1) נסרקו רק ל-720 המילים הראשונות בקולומביה** (1,188 הושמטו) ולא בצביר עשירי; שורות הן טקסט רגיל ואינן ELS.
- **המילון הוא `gematria_words`**: 4,873 מילים בודדות באורך 2–9, לא לקסיקון עברי מלא. חסרות בו צורות סמיכות/נטויות (`ספינת`) ומילים נפוצות (`יכל`) — זו הסיבה העיקרית ל-recall נמוך בדוגמה.
- **הסטטיסטיקה היחידה היא צפיפות מילון.** היא לא מודדת קוהרנטיות סמנטית ולא סימטריה/סמיכות לעוגן — בדיוק מה שנראה בקולומביה.
- אריחי הבקרה אינם בלתי תלויים, ובחירת היעד היא post-hoc (ראו סעיף ההשוואה).
- **לא בוצעה קריאת מודל חי מבודדת.** הקיבוץ נכתב על ידי אותו Claude שראה את מילות היעד בשיחה, ולכן אין כאן עצמאות; מובטח רק שהחבילה אינה מכילה אותן. `claude-raziel` דורש JWT של אדמין, ולא נוצר מסלול AI חדש. להרצה עיוורת אמיתית: להדביק `packet.txt` ב-`claude-raziel` או בשיחה חדשה בלי מילות היעד, ולהריץ `validate` ואז `report`.
- אותו קוד רץ על שתי דוגמאות בלבד.

## כיוונים שהניסוי מצביע עליהם (לא יושמו)

1. **זיהוי מבני סביב העוגן**: זוגות ממצאים בתמונת מראה סביב ציר העוגן, וצירופים סמוכים באותו קו — סינון גנרי שמאפשר לכלול מילים קצרות בלי להיחנק מרעש.
2. **הרחבת הלקסיקון** (צורות סמיכות/נטויות) — המנוף הגדול ל-recall.
3. **מילון זרע לפי נושא**: המודל מציע מילים מהנושא בלבד, המנוע מאמת מיקומים (כמו ה-probe), והמילים לא נחשפות מראש — בדיקה עיוורת אמיתית.
