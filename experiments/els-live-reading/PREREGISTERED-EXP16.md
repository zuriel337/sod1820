## 2. Series (never pooled)
* **blind** — nothing that depends on a target is in the input or the code; no hint of any kind. The evaluation targets are read only by the summary stage, only for Columbia runs, after every answer is saved.
* **planted** — blind, with known truth: the harness plants known Hebrew words in a real window; the model is not told.
* **diagnostic** — the model is given a hint chosen after we knew what EXP-15 missed. Reported in its own section, labelled NOT BLIND; it can show whether a hint changes what the model proposes, never that the model discovered something.

## 3. Regions
* Control windows `w01..w08` (33 rows x 41 columns of the width-4545 Torah matrix, the Columbia shape): chosen by `sampleWindows` with the seed label `EXP16-control-windows-v1` (mulberry32 over the first 4 bytes of its SHA-256), rows start in [0, 34], columns keep a margin of 21 from both edges, no cell shared with another window or with the Columbia region. The first k windows do not depend on n. The windows were chosen from the seed alone; their letters were fetched afterwards.
* Letters come from the text embedded in the page (a second copy of `public.torah_stream`), and **every whole window is compared with the canonical table by an md5 computed in SQL** (`review/window-md5.sql`, result in `review/window-md5-canonical.json`): all eight are equal.
* Planted windows `p1` (on `w07`) and `p2` (on `w08`): six words each, registered in `lib/plant.mjs` before any call: kinds R, C, D, A each at least once, two read in the `-` direction, distances from the window centre near (<= 6), mid (7-12), far (>= 13), types word / phrase / name; positions drawn from the seed label `EXP16-planting-v1:<window>`; no overlapping cells; the untouched window is kept and compared with the page. A planted window is synthetic: its letters are not in the stream, so a proposal is verified against the window's own letters (`verified_synthetic`), never against the engine.

## 4. Prompt v2 (same instruction text in every arm)
Only the data and the background paragraph differ between arms. `story`: `columbia` = ZURIEL's sentence, `wrong` = "קונצרט ענק באצטדיון, שבו אלפי אנשים שרו יחד עד חצות", `none` = "no description and no topic" (story_related is then false). `marked`: only the Columbia region has a selected occurrence; in every blind v2 arm nothing is marked or named (the earlier run named and marked it). The boundary sentence says that the region is cut on all four sides. The task adds `tier`: A (at most 12 proposals "I would show first"), B, C — a presentation order, not a filter, with an explicit instruction not to rank by closeness to the middle or by line type. The continuation option of EXP-15 (letters before/after, crossings, near grid, `from_finding`) is unchanged. `S1` is the EXP-15 request byte for byte (same SHA-256 `a8eb021b…`): it measures run-to-run variance.
Settings for every run: `claude-fable-5-1`, adaptive thinking (summarized), effort `medium`, `max_tokens` 64,000, structured output, no tools, no fallback, Message Batch.

## 5. Runs and order
Priority 1 (story control, blind): `S2` Columbia + story, unmarked; `S3` Columbia + wrong story; `S4a-f` six random windows + Columbia story; `S1` exact repeat of EXP-15.
Priority 2 (no story, no topic, blind): `N1` Columbia; `N2a-d` windows w01-w04 (the same windows as S4a-d, so that the two prompts can be compared on the same text); round 2 (continue before/after, cards built by the harness from the model's own verified proposals that asked to continue, at most 6 cards) for N1 and N2a-d.
Priority 3 (planted, blind): `P1`, `P2`.
Priority 4 (diagnostic, last): `D1` two full lines that pass next to the selected occurrence, asking for every reading; `D2` Columbia + story + occurrence marked + a hint to propose names, acronyms and splits. Run only if spent <= USD 26 when priority 3 is done.
Order inside priority 1: `S2`, `S3`, `S4a` first (checkpoint 1: report actual cost and output tokens; if the mean cost is above USD 1.30 per run, or any run ends without a usable answer, stop and report before continuing), then the rest. A run that ends with `max_tokens` or an unparseable answer is recorded as failed and its cost counted; it is **not** repeated automatically.

## 6. Verification
As in EXP-15: letters at the claimed positions from `public.torah_stream` plus, for skip >= 2, the canonical engine `els_search_page_core_v1` returning an occurrence with the same start and direction; skip 1 rows are plain text only. When the engine's first page (100 hits) is cut before the claimed start, the same function is asked for the keyset continuation just before that start and the result is recorded as such. Nothing is filtered by dictionary, rarity or geometry; verified and not verified are shown separately.

## 7. Metrics (all descriptive; no test statistic is computed)
* per run: proposals, verified, not verified; verified by engine / plain text / synthetic; length classes of ELS proposals (3-4, 5-6, 7+ letters); **long** = at least 5 letters; **chance-expected** E = 2 x (N - (L-1) x skip) x product of f(letter) over the L letters, with N = 304,805 (the Torah stream; the page's first 304,805 letters must equal it by md5 `0066c243…`, computed by SQL over `public.torah_stream`) and f the Torah's own letter frequencies: the number of occurrences of that run expected anywhere in the Torah at that one skip if letters were independent. **unlikely by chance** = E < 1 (also reported: E < 0.1). E is the noise baseline, never a filter: a verified ELS proposal with E >= 1 is *expected* to exist somewhere at that skip. (Real text has digram structure, so observed counts often exceed E; the engine's own count is reported next to it, and **rare** = at most 3 occurrences at that skip by the engine, a truncated page counting as not rare, is secondary.) The proxy for a first-group candidate that is "interesting" is: verified ELS, >= 5 letters and unlikely by chance. Noise measures: the share of ELS proposals with E >= 1, the share of short (3-4 letters) ELS proposals, and the plain-text share; plain-text share; story_related counts; kinds of line (R, C, D, A) for ELS proposals; continuation counts (`from_finding`, extension, crossing, phrases).
* **story control**: per run, the number of verified ELS proposals with >= 5 letters that the model flags as related to the story, the number with >= 5 letters in all, and the number unlikely by chance (E < 1); compared across Columbia (S1, S2, EXP-15), the wrong story (S3) and the random windows (S4a-f). The Columbia targets are looked up afterwards, only in Columbia runs.
* **first group** (tier A): its size, composition (ELS vs plain, long, rare, line kinds, story-related), and what it would lose: verified long rare ELS proposals outside tier A. The tier is the model's own and is assigned in the same call, so it is not an independent judge; its quality can be measured against truth only in the planted windows (found words that are in tier A).
* **planted recall**: each planted word is `exact` (a verified proposal whose cells are exactly the word), `contains` (a longer proposal that includes it), `overlaps` (two or more shared cells) or `missed`; recall by line kind, distance class, direction and type; how many found words were in tier A; invented runs (not verified).

## 8. What each outcome means (fixed now)
* The numbers are counts over a handful of windows. Nothing here is "significant"; a difference must be large and consistent across windows to be worth a follow-up.
* **A null or negative result in Columbia** (the Columbia-specific proposal does not repeat in `S1`/`S2`, or random windows with the same story give comparable counts) is a result about **this method and these settings only**: prompt v2, `claude-fable-5-1`, effort medium, one-round reading of a 33x41 region with four line types. It does **not** close the discovery direction and says nothing about other methods (for example selection from a structural candidate pool, EXP-12), other models, other prompts or other cases.
* **A positive result** (the proposal repeats, is absent from the wrong-story and random arms) justifies a larger blind comparison; it is not a finding.
* Diagnostics show what a hint changes; they are never evidence for discovery.
* The unmarked arms use the Columbia region without naming the occurrence; whether the model finds anything near it is then a property of the text and the model, but the region was chosen around that occurrence, so the Columbia region is not a random region.
