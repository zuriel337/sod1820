# EXP-15 — קריאת עברית חיה באזור מוגבל של מטריצה (מקרה ראשון: קולומביה)

**סטטוס: מוכן לסקירה. לא הופעל שום מודל.** ההגדרה המוקדמת: `PREREGISTERED-LIVE-READING.md`. מה יישלח בדיוק: `review/request-round1.txt` (הודעה קריאה) ו-`review/request-round1.json` (הבקשה), שניהם עם אותו SHA-256.

## מה המודל מקבל
תיאור כללי (המשפט שלך, כלשונו), האזור והגבולות שלו, גריד, ו-212 קווים בשני הכיוונים (424 קריאות), הנחיה לחפש מילים וביטויים בעברית תקינה כולל צורות לשון וסמיכות, חלוקות שלא משנות אותיות, ו**אפשרות להמשיך ממילה שנמצאה**: האותיות לפניה ואחריה באותו קו, שלושת הקווים האחרים שחותכים כל תא שלה והסביבה הקרובה (`from_finding`, `kind` = extension / crossing, `continue_from`). בלי מקומות, דילוגים או רוחב מטריצה, ובלי מילות היעד.

## הרצה (ממאגר ה-worktree; ה-SDK מותקן רק כאן: `cd experiments/els-live-reading && npm install`)
```
# 1. סקירה, בלי רשת ובלי מפתח
node experiments/els-live-reading/run-live-reading.mjs dry-run --model <id>
# 2. בדיקת זמינות (דורש ELS_EXPERIMENT_ANTHROPIC_KEY; לא מחייב טוקנים): המודל ברשימה? יכולות? ספירת קלט מדויקת? תקרת עלות עליונה?
NODE_USE_ENV_PROXY=1 node experiments/els-live-reading/run-live-reading.mjs preflight --model <id>
# 3. הקריאה, רק עם ה-SHA של הבקשה שנסקרה ותקרת עלות
NODE_USE_ENV_PROXY=1 node experiments/els-live-reading/run-live-reading.mjs call1 --model <id> --approve <sha256> --max-usd <usd>
# 4. אימות: sql → הרצת קבצי ה-SQL (קריאה בלבד) → ingest
node .../run-live-reading.mjs sql ; node .../run-live-reading.mjs ingest --results <קובץ תוצאות>
# 5. סבב 2 (אופציונלי, בקשה נפרדת עם SHA משלה): round2 → סקירה → call2
# 6. דוח, ורק בו יעדי ההערכה
node .../run-live-reading.mjs report --targets experiments/els-live-reading/evaluation/targets.json
```
בלי המפתח כל שלב קריאה מסתיים בקוד יציאה 2 ובהודעה "no credential"; אין נתיב מדומה.

## מה נבדק כבר (בלי מודל)
- האזור: 1,353 תאים, כל שורה עם md5, 0 הבדלים מול העמוד; המופע הנבחר (טור 21, שורות 21–28) מאויית `קולומביה` ותואם התחלה 248765, דילוג 4545.
- כל אחת מ-424 הקריאות: ההתחלה, הדילוג והכיוון שנגזרו מחזירים בדיוק את אותיות הקריאה מהעותק השני של הטקסט.
- ה-SQL של האימות מול המנוע הקנוני החי: בקרה חיובית (המופע הנבחר) מאומתת, בקרה שלילית (הזזה באות אחת) נדחית, ושורה רגילה מאומתת כטקסט רגיל בלבד (`review/verification-selftest.json`).
- הקישוריות: נתיב ה-SDK מגיע ל-API ומטפל בדחיית מפתח (`review/connectivity-check.json`). האם מפתח אמיתי עובד — לא נבדק; זה השלב הראשון של ה-preflight.
- 12 בדיקות יחידה (`test/els-live-reading.test.mjs`), כולל: אין מילות יעד בקוד או בנוסח ההנחיות, הבקשה שנסקרה היא זו שנבנית, ונכשל סגור בלי מפתח.

## מגבלות
- נתוני האזור מועברים בהעתקה ממנוע (md5 לכל שורה) ולא בחיבור ישיר; בדיקת העותק השני בעמוד סוגרת טעויות העתקה.
- הגריד והקווים כוללים בהכרח את אותיות היעדים כרצפים (הן חלק מהמטריצה); הם אינם מופיעים בנוסח ההנחיות, בסכמה או בקוד.
- עלות: ספירת הטוקנים מדויקת תיתן רק ה-preflight; העלות בדוח תחושב מנתוני `usage` ומהמחירון (מטמון 2026-10-06), לא מחשבונית.
- האימות בודק אותיות ומיקום בלבד; משמעות היא פרשנות של המודל.
