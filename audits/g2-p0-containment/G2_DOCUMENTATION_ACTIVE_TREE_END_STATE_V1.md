## Human-Gate vision

The 2029 system is one large tree growing upward from a broad, stable Foundation. During construction, many audits, drafts, historical contracts, research notes, migration records and superseded plans may remain around the tree as provenance. They must not become competing active guidance.

The target end-state is a **clean active tree**: a fresh agent can continue from the current canonical spine without reading historical debris. Historical work is preserved, but removed from the active routing surface into archive/provenance locations.

## Important distinction

`ZERO HISTORICAL DOCS IN ACTIVE ROUTING SURFACE` does **not** mean deleting history.

- Preserve git history, audit evidence, prior decisions, superseded contracts and research provenance.
- Archive/supersede them so they are not default startup context.
- Historical material is read only for DRIFT, provenance, recovery, migration or explicit historical research.

## Active documentation classes

Only these may remain on the active path after final reconciliation:

1. **ACTIVE SPINE** — Owner Index, current Roadmap, current Master State/pointer surface, runtime entry adapters.
2. **CURRENT DOMAIN OWNER** — the one current owner/contract for a responsibility.
3. **CURRENT ADDENDUM** — only when an additive current layer is still required and clearly points to the owner it extends.
4. **LIVE IMPLEMENTATION POINTERS** — only documents required to operate, verify or maintain the current system.

Everything else is non-startup material:

- `AUDIT / EVIDENCE`
- `HISTORICAL / SUPERSEDED`
- `DRAFT / EXPERIMENT`
- `RESEARCH NOTE / EXTRACTION ARTIFACT`
- `MIGRATION / RELEASE PROVENANCE`

These remain preserved but must not compete for active authority.

## Mid-build rule — do not stop the tree to clean the forest

During G2/G3 and later construction, do **not** bulk-move hundreds of files merely for tidiness. That can break links, obscure provenance and consume attention while semantics are still changing.

Instead:

- keep routing clean now;
- forbid new parallel "master/final/system" documents without owner resolution;
- put new gate evidence under the relevant `audits/<gate-or-scope>/` lineage;
- mark supersession explicitly when touched;
- perform physical archive moves in bounded reconciliation passes at stable gate/program boundaries.

## Final documentation reconciliation pass

Before declaring the 2029 program/documentation surface clean, run a finite census and classify every documentation artifact:

`ACTIVE_SPINE | CURRENT_OWNER | CURRENT_ADDENDUM | LIVE_OPERATIONS | ARCHIVE_AUDIT | ARCHIVE_HISTORICAL | ARCHIVE_DRAFT | ARCHIVE_RESEARCH_PROVENANCE`

Acceptance target:

- no superseded contract presented as current;
- no duplicate active owner for one responsibility;
- no historical W/G checkpoint required for normal startup;
- no draft/research note in the active routing path;
- all archive moves preserve provenance and inbound-pointer reconciliation;
- fresh-agent startup remains owner-first and minimal-read.

## Future-growth starting point

The current Master Roadmap already reserves **W9 — Multilingual + spatial + multi-surface future**. The clean-tree target therefore fits the intended architecture: after the core 2029 tree is closed, future growth can extend the same identities and capabilities into English/additional languages and mature spatial 2D→3D→AR/VR / multi-surface renderers without rebuilding the Foundation or forking the tree.

This does not assert today that no other maintenance or future capability will ever exist. It means new work starts from the clean canonical tree rather than from accumulated historical documents.
