## 1. Purpose

This gate exists to prevent accumulated G2 history, work logs, superseded rules, branch artifacts and duplicated documentation from becoming the operating map for G3.

It does **not** delete history and does **not** create a new Master, Registry, Rule System, Contract System, Owner System or Archive System. It operationalizes principles already owned by `foundation_closure_protocol_law`, `inter_agent_coordination_law`, Master State governance and the Canonical Owner Index.

Target operating spine:

`Master State → Master Roadmap → Owner Index → owner families → current active owners → implementation/live state`

Historical rules, work logs, audits, branches and superseded decisions remain available for DRIFT, provenance, migration, recovery and explicit source research, but are not normal startup material.

Core doctrine:

> **Current first → history on demand.**

## 2. HARD G2 CLOSURE BLOCKER

**G2 MUST NOT BE DECLARED CLOSED until this gate passes.**

Passing Foundation/Product Capability proofs is necessary but not sufficient. Before formal G2 closure the project must complete bounded semantic compaction, owner-family reconciliation and Active Tree Freeze.

The closure pass MUST prove all of the following:

1. **0 orphan active laws.** Every active rule is classified explicitly as one of: `OWNER` · `CHILD_OF_OWNER` · `IMPLEMENTATION_OR_PROJECTION_RULE` · `LEGACY_RETIRE_OR_SUPERSEDE`. No active rule may remain semantically ownerless merely because it is old or familiar.
2. No active rule family has conflicting simultaneously-active versions.
3. Owner families form a readable hierarchy instead of a flat list of hundreds of rules. The hierarchy should reuse existing `rule_id`, `depends_on`, owner metadata and the Owner Index where appropriate; no new hierarchy store is authorized.
4. `SOD1820_MASTER_STATE.md` is replaced by a **compact current-state form** after preserving the pre-compaction Master byte-for-byte as historical provenance. The compact Master contains current architecture/state, exact release states, material Human-Gate decisions, open blockers and pointers — not copied owner bodies or audit stories.
5. `SOD1820_MASTER_ROADMAP.md` contains only navigation, priorities, mandatory gates, current sequence and explicit open decisions. It is not a second Rulebook or Change Log.
6. `SOD1820_MASTER_OWNER_INDEX.md` is the finite domain → canonical owner routing spine and resolves active owner families without requiring broad work-log archaeology.
7. `work_log` remains append-only provenance, but normal startup operates from a **bounded current/open surface**: active assignments, unresolved blockers/handoffs, current release state and recent material Human-Gate decisions not yet reflected by their canonical owner/pointer.
8. Branch-only / implemented / committed / merged / deployed / live / verified are reconciled for material surviving work.
9. Superseded/legacy upper-layer semantics are clearly classified as historical/migration evidence and cannot silently outrank current owners.
10. **ONE DECISION → ONE CANONICAL BODY.** A semantic decision has one authoritative body. Master/Roadmap/Owner Index/audit/work_log/project_codex may point to it as appropriate; they must not all carry competing full copies of the same semantics.
11. A fresh agent can resolve representative tasks across Gematria, Raziel, Research OS, ELS, Books/Sources, Person/Life, Publishing, Follow/Attention, Experience and Release using the smallest relevant read set, without relying on prior conversation memory or broad historical scans.
12. The project has an explicit **future-admission rule** preventing re-inflation after cleanup: architecture/state/closure/Human-Gate material → Master pointer; domain semantics → owner; priority/sequence → Roadmap; research findings/examples → Research OS; coordination/execution trace → work_log; release evidence → release/work_log provenance.
13. A second mandatory **G3 Implementation Compaction / Archive Pass** is already recorded in the program so G3 cannot accumulate a new active-history pile unchecked.

If any of these fail materially, G2 remains OPEN.

## 4. Active-rule classification contract

Every active rule at closure receives exactly one routing classification:

- **OWNER** — canonical semantic owner for a bounded domain/responsibility.
- **CHILD_OF_OWNER** — scoped law whose semantic parent is an existing canonical owner family.
- **IMPLEMENTATION_OR_PROJECTION_RULE** — operational/presentation behavior subordinate to an owner; it does not become a competing semantic owner.
- **LEGACY_RETIRE_OR_SUPERSEDE** — preserved historical/compatibility law that must not participate in current routing after freeze unless explicitly invoked for legacy behavior.

The classification itself must point to the current owner/family where applicable. Labels alone are insufficient if a fresh agent still cannot route deterministically.

Acceptance = **100% active rules classified** and **0 material orphan active laws**.

## 5. Work-log compaction target

`work_log` stays append-only provenance. Do not delete or rewrite historical rows merely to make counts smaller.

Normal startup must operate from a bounded current view containing only what can change the present task, such as:

- active assignments / active writers;
- open blockers / unresolved handoffs;
- current release blockers/state;
- latest material authoritative AFTER for the active scope when needed;
- recent Human-Gate decisions not yet represented by an owner/Master pointer.

Everything else is Archive/Provenance material.

A fresh agent must not need to scan thousands of completed rows to infer current state. If `work_log_current` or its successor still behaves like almost-full history, this acceptance item is NOT PASS.

## 6. Rule-history compaction target

Inactive/superseded rule versions remain preserved.

Normal routing reads:

`intent/domain → owner family → current active owner/version → direct dependencies`

Historical versions are opened only for conflict resolution, provenance, migration, recovery or explicit historical research.

No physical deletion of inactive rule versions is required by this gate.

### Master State v3 Compact

### Owner Index

Finite domain → canonical owner → active/current version/status → implementation pointer routing map, plus owner-family routing sufficient for fresh agents.

### Work Log

Coordination, provenance and historical execution trace. Not Product SSOT.

### Research OS

Atomic Findings, source calculations, procedures, examples, anomalies and research evidence live here — not in Master/Roadmap.

## 8. ONE DECISION → ONE CANONICAL BODY

At compaction, every material surviving semantic decision must have exactly one authoritative body.

Examples:

- operational domain law → active `nodes.rule_id` body;
- long-form architecture/contract → its canonical `project_codex`/main contract owner;
- documented project state → Master pointer/state line;
- navigation/priority/gate → Roadmap;
- execution/handoff/release evidence → work_log;
- atomic research evidence → Research OS.

Other surfaces may contain concise pointers/status summaries only.

If two current bodies claim the same semantic authority, resolve by owner/supersession before G2 closure; do not leave “both are kind of current”.

## 9. Future-admission / anti-inflation rule

After compaction, new material enters the smallest correct home:

- **Master:** only material architecture/state/closure/Human-Gate change + pointer/status.
- **Roadmap:** only priority, navigation, mandatory gate, sequence or explicit open decision.
- **Owner body:** domain semantics/rules/contracts.
- **Research OS:** findings, examples, calculations, source evidence, procedures, anomalies.
- **work_log:** coordination, writer state, handoff, execution/release provenance.
- **Archive:** superseded/historical bodies retained for provenance.

A detailed audit must not be pasted wholesale into Master merely because it was important. Importance may justify a Master pointer; it does not justify body duplication.
