## 358 experience — rich without becoming a dashboard dump

358 qualifies for a deep projection because several independent semantic families are populated: calculations/expressions, graph relations, media over long time coverage, ELS research material, Research Objects and historical Post material.

The surface should therefore be able to progressively reveal:
1. **Identity nucleus** — Number 358 and exact sibling identities such as Expression `משיח`, never flattened into one label cloud.
2. **Verified calculation field** — real method switching with downstream projection updates; calculation is replayable and method-specific.
3. **Research findings** — typed stage/verification/governance/access kept distinct.
4. **Evidence/source lineage** — group by source/artifact dependency before any strength claim.
5. **Relations / explain-why** — semantic path through intermediate Findings/Observations where needed, not merely a dense graph picture.
6. **Representations** — media, Posts, gallery placements, ELS visuals and other renderings as views of the same research reality.
7. **Temporal evolution** — known milestones/occurrences without rewriting unknown history.
8. **Research continuity** — save/add-to-research, compare, Journey, exact return and Raziel next-action planning.

A single opaque “358 score” is specifically rejected by the active owners. If a compact richness signal is later desired, it must remain an explainable projection over separate dimensions and cannot substitute for Truth/Governance.

## Negative / missing / inaccessible outcomes

The Hub must be able to show honest capability outcomes without manufacturing content:
- `NEGATIVE_RESULT` — bounded check executed and did not find the target; show scope/reason and no fake Finding.
- `MISSING_ADAPTER` — the semantic capability exists/was requested but the current adapter path does not; offer no invented answer.
- `EXECUTED` with zero Finding refs — may be projected as an executed-empty result; do not create a fake global status called `executed_empty`.
- `UNVERIFIED` — result exists but replay/verification is not established.
- `CONTEXT_REQUIRED` — capability needs a source/book/corpus/person context before execution.
- `ENTITLEMENT_GATED` / inaccessible state — access is blocked, but underlying Truth is unchanged.
- `FAILED` — execution failure is operational, not negative evidence.

Exact wording/icons/empty-state composition are deferred; the semantic distinctions are Foundation-backed now.
