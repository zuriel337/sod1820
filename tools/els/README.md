# הצופן התנכי — כלי דילוגי-האותיות (ELS)

מקור-האמת של הכלי **«הצופן התנכי»** שרץ ב-`sod1820.co.il/code` וגם בהיכל (`/research?tool=els`).

## מה זה
כלי **עצמאי (vanilla-JS)** לחיפוש דילוגי-אותיות בכל התנ״ך. אותיות הקורפוס הקנוניות
(1,204,583 אותיות, 24 ספרים), גבולות הפסוקים ומנוע החיפוש מוטמעים ב־`public/tzofen.html`
כ־gzip+base64 ומפוענחים בדפדפן ע״י `DecompressionStream` (בלי ספרייה, תואם-CSP).

טקסט-הפסוקים המלא, שמשמש לתצוגת מקור בלבד, נבנה כנכס gzip בינארי ותוכן-ממוען תחת
`public/els-data/`. הוא אינו נטען בפתיחה, בזמן idle או בחיפוש רגיל; הפעולה הראשונה שמציגה
מקור/פסוק/אות מושכת אותו מאותו origin, מפענחת אותו במפורש ומאמתת SHA-256 של המקור.
הסימון `.gzdata` מכוון: הדפדפן אינו מסתמך על כותרת `Content-Encoding` של השרת.

המחולל אינו סורק או מוחק רשומות קיימות תחת `public/els-data/`. בנייה חוזרת מאותו מקור
משתמשת שוב בשם התוכן־ממוען ואינה מוסיפה נכס; בנייה ממקור אחר עשויה להשאיר גם נכסים ישנים.
קובץ זר, שם כמעט־תואם, תיקייה, symlink, FIFO או כל רשומה מיוחדת נשמרים כפי שהם, וה־HTML
החדש תמיד מפנה לנכס הנוכחי שנכתב ואומת באותה עסקת פרסום.

פרסום האתר נעול בין תהליכים לכל העסקה `asset → HTML`. זהות הנעילה נגזרת מהנתיב
הקנוני של `public/`, וקובץ הנעילה נמצא בתיקיית ה־temp של המערכת, מחוץ לעץ המתפרסם. נעילת
הקרנל משתחררת גם בחריגה או ביציאת תהליך. כתיבה אטומית ושמירת הנכס הישן מבטיחות שאחרי כשל
תהליך נשאר זוג ישן או חדש שמיש; אין כאן טענת durability מול אובדן־חשמל, כי פלט האתר
והתיקיות המכילות אותו אינם עוברים `fsync`.

## איך זה מוטמע באתר
`public/tzofen.html` מוצג כ-**iframe** דרך הרכיב `src/components/TzofenEmbed.jsx`
(אותו דפוס כמו `public/heichal.html`). מוצג ב:
- `src/pages/CodePage.jsx`  → `/code` (עמוד מלא)
- `src/pages/ResearchPage.jsx` → `/research?tool=els` (בהיכל/סביבת-המחקר)

הגשר iframe↔אתר (ב-`TzofenEmbed`): (1) שולח דרגת-משתמש (`postMessage tier`), (2) רושם כל חיפוש
דרך `track("els",…)` הקיים → `events`+`visitor_events`, (3) מציג `SubscribeGate` בשער-ההרשמה.

## מנוע אחד — אין מימוש שני (`els_single_engine_law`)
**קיים בדיוק מנוע-ELS אחד בפרויקט:** `tools/els/els-code.template.html` → `build.py` → `public/tzofen.html`.
כל המשטחים מטמיעים את **אותו iframe בדיוק** (`TzofenEmbed.jsx`, נתיב קשיח `/tzofen.html?embed=1`):
`/code` · `/research?tool=els` (ההיכל) · `/codes/:slug`. ההבדל היחיד בין המשטחים הוא ה-prop `full`
(גובה ה-iframe בלבד) — הבדל-UI, לא הבדל-מנוע.

⛔ **אין להחזיר מנוע שני.** המימוש הישן (`ElsGrid.jsx` · `features/els/Els.jsx` · `lib/els/*` ·
`SearchJourney.jsx` · `lib/research/torah.js` · `els-demo.html` · ראוטי `/code/ארכיון`) **הוסר במלואו**
(15.8.2026). ארבע יכולות שהיו רק בו נרשמו כדרישות-עתיד ולא מומשו: התאמה-מקורבת (`maxMismatches=1`) ·
היקף ספר-בודד · תבניות-דילוג (חזקות-2/פיבונאצ׳י/ראשוניים) · Web Worker. פרטים ב-`work_log`.

### מקור-הקורפוס — יחיד
`tools/els/data/tk-letters.txt` הוא **קורפוס החיפוש הגולמי היחיד** והקלט של `build.py`.
העותק הכפול `public/tanakh-letters.txt` (בייט-בבייט זהה) **הוסר** כדי שלא ייראה כמקור-אמת שני.
מנוע החיפוש נשאר מוטמע ועצמאי. רק `tk-vtext.txt`, שאינו משתתף בחיפוש או בחישוב תוצאה,
נמשך כנכס תצוגה לפי דרישה. כשל רשת, פענוח או hash נכשל-סגור בהצגת הטקסט בלבד; הוא אינו
מחליף טקסט, אינו משנה תוצאה ואינו משבית את החיפוש. ניסיון פעולה מאוחר יכול לטעון מחדש.
`public/torah-verses.json` ו-`public/tanakh-verses.json` נשארו — הם משרתים כלים חיים שאינם ELS
(VerseSearch · NotarikonTool · NameStory · VerseGematriaPage).

## בנייה / עריכה
```bash
cd tools/els
python3 build.py
# → כותב אטומית public/tzofen.html + public/tzofen-standalone.html
#   + public/els-data/tk-vtext.<sha16>.gzdata

python3 build.py --standalone-out /tmp/tzofen-offline.html
# → יוצר קובץ HTML עצמאי חדש; אינו דורס יעד קיים ואינו משנה את פלט האתר
```
- **לערוך את הכלי:** משנים את `els-code.template.html` (זה המקור — ~190KB, כל ה-HTML/CSS/JS),
  ואז `python3 build.py`. **לא לערוך את `public/tzofen.html`, את
  `public/tzofen-standalone.html` או את הנכס תחת `public/els-data/` ישירות** — שלושתם
  פלטים דטרמיניסטיים.
- **פלט Legacy ציבורי, לא מנוע נוסף:** `public/tzofen-standalone.html` נוצר מאותה תבנית,
  מאותו קורפוס ומאותו render מוקשח. הוא מטמיע רק מתאם replay מקומי שבודק את מועמדי אותו
  מנוע, מציג את כרזת Legacy, מבטל כתיבות אחסון ומסתיר פעולות שמירה/שיתוף. הוא מתפרסם
  תחת אותה נעילת־תהליך ובכתיבה אטומית כמו הפלט המתארח, ומשמר את `/tools/tzofen/` בלי
  להחזיר מנוע חיפוש, state או store מקבילים.
- **ארטיפקט אופליין נתמך:** `--standalone-out` מטמיע את אותם בתים דטרמיניסטיים של gzip
  כ־data URL בתוך HTML יחיד, עם אותו SHA-256 ואורך-מקור. חיפוש ELS רגיל משתמש באותו מנוע
  דפדפן ובמתאם replay מקומי שבודק כל מועמד מול קורפוס-האותיות הקנוני המוטמע; הקשה על אות
  מציגה את ההפניה ואת טקסט-הפסוק המלא בלי קובץ-אח. תיקיית־האב נפתחת רכיב־אחר־רכיב בלי
  לעקוב אחרי symlink, נשארת קשורה באמצעות file descriptor לאורך הבדיקה, ה־render, הכתיבה
  והאימות, ונבדקת לפי זהויות inode שאינה בתוך הריפו. ההוצאה היא **create-new בלבד**: יעד
  קיים מכל סוג נדחה; קובץ זמני מלא עובר `fsync` ואז מתפרסם בקישור אטומי שאינו דורס יעד
  שנוצר במרוץ. יעד בתוך `public/`, `dist/`, `inputs/` או כל מקום אחר בריפו, רכיב־אב מקושר,
  יעד קיים או תיקיית־אב חסרה נדחים בלי שינוי בפלט האתר. שינוי נתיב האב אחרי הבדיקה אינו
  יכול להסיט את הכתיבה לנתיב החלופי. ליצירה חוזרת משתמשים בשם חיצוני חדש או מסירים במפורש
  את הארטיפקט הקודם; אין להוסיף עותק כזה לנתיב אתר נוסף מעבר לפלט Legacy הקנוני שמייצר
  המחולל עצמו.
- הטעינה המתארחת היא מאותו origin ומתאימה למדיניות `connect-src 'self'`. ארטיפקט standalone
  טוען `data:` מתוך עצמו ולכן מדיניות CSP חיצונית שמוחלת עליו חייבת להתיר `data:` ב־`connect-src`;
  פתיחה ישירה ב־`file://` כפופה גם למדיניות ה־file-origin של הדפדפן או המכשיר.
- ארטיפקט האופליין אינו מחליף יכולות שרת: exhaustive ordered pages, שמירה/ספרייה/חשבון,
  הרשאות ו־trace שרת נשארים יכולות של האתר. לכן replay אופליין מסומן בנפרד ואינו נטען לפלט
  האתר; `public/tzofen.html` ממשיך להשתמש בגשר האימות הקנוני של השרת.
- `data/` = מקורות הבנייה: `tk-letters.txt` (אותיות התנ״ך המנורמלות), `tk-vtext.txt`
  (טקסט-פסוקים שנארז בנפרד), `tk-vlens.txt`/`tk-vchap.txt`/`tk-meta.json` (אינדקס-פסוקים מיושר),
  `niqqud-compact.txt` (ניקוד-תורה), `els-logo-b64.txt` (לוגו ELS של האתר).
- לפני render או כתיבה המחולל דורש `tk-vtext.txt` ב־UTF-8 תקין, LF סופי, בדיוק 23,204
  שורות מיושרות ל־`tk-vlens.txt`; סכום אורכי־הפסוקים חייב להיות 1,204,583, ומפתח הפרקים
  והספרים חייב להגיע לאותו מספר פסוקים. קלט שהדפדפן היה דוחה לעולם אינו מתפרסם.
- מקורות-הנתונים המקוריים: `public/tanakh-letters.txt` + `public/tanakh-verses.json`
  (התורה יושרה למהדורת-304,805; הנ״ך 1:1). ראה `work_log` לפרטי-היישור.
- **`tk-vtext.txt` (תצוגת-הפסוק) נבנה מחדש ממקור נקי (Sefaria/WLC):** במקור המקף (־)
  נמחק בלי רווח → מילים נדבקו («כלעדת בניישראל»). התיקון: טקסט-פסוקים נקי מיושר
  לגבולות-הפסוק הקיימים (זרם-האותיות אומת זהה 39/39 ספרים → אפס-סחף). משפיע רק על
  תצוגת-הפסוק בחלונית, לא על החיפוש/הדילוגים. הסקריפט: `scratchpad/rebuild_vtext.py`.

## פיצ׳רים (נכון ל-14.7.2026)
- 3 מצבי-תצוגה: מלכותי · **קלף** · קלאסי.
- היקף: 📖 תורה (מהיר) · 🔒 **כל התנ״ך נעול לרשומים** (בלי טעינת-כוח עד שנפתח).
- עיגון-פסוקים (הקשה על אות → ספר·פרק·פסוק + טקסט), חיפוש-מוצלב (לרשומים), עדשות/מתקדם (אדמין),
  PNG · סרט-הצופן (כל פתיחת-צופן מתנגנת כסרט; ביקור-ראשון ×2 על «תורה קדשה»), שיתוף, גלריה.
- **🎓 שער-הדרכה חובה + מאמן-שיטה (21.7.2026):** הנתונים הראו שאנשים מקלידים משפט שלם כמחרוזת-דילוג (ממוצע 10.9 אותיות!) → «לא נמצא» → מתייאשים. התיקון: (1) **שער-הדרכה חד-פעמי** «איך מחפשים נכון» (`openOnboard`, flag `tzofen_onboarded_v1`) נפתח לפני החיפוש הראשון וחוסם אותו — 3 צעדים: מילה קצרה 2־5 אותיות · דילוג נמוך · **הצלבה = «החיפוש המוצלח»**; (2) **מאמן-קלט חי** (`updateCoach`) — משפט/מילה-ארוכה → רמז מתחת לשורה + כפתור «🔀 פצל והצלב» שמפצל לשני שדות (`splitToCross`); (3) ברירת-המחדל «יום משיח בא» הוסרה — הכלי כבר לא מלמד את ההרגל הרע (placeholder+שבבים = מילים קצרות).
- **שער-גישה:** לא-רשום = **קריאת ההדרכה** + `FREE_DEMO=3` חיפושי-מילה לטעימה · **מוצלב + כל התנ״ך + שמירה = לרשומים** («החיפוש המוצלח» דורש רישום) · אדמין = הכל.
- **שמירת-מטריצה = לענן בלבד** (בלי שמירה-למכשיר): «💾 שמור בגלריה» → `postMessage(save)` → `TzofenEmbed` קורא ל-`save_els_matrix` → `els_records`. אדמין → `published` מיד · משתמש רשום → `pending` (אישור בדשבורד) · אנונימי → שער-הרשמה. הגלריה נפתחת מכפתור «🖼️ מטריצות שמורות» (`SavedMatricesGallery`, קורא `published`).
- **אדמין:** 5 הקשות על הכותרת / `#admin` בכתובת → עריכת-צפנים, קשר-לפוסט.
- **דשבורד:** טאב «🔠 הצופן» ב-`AdminPage` (`src/components/ElsStatsTab.jsx`) קורא מ-`visitor_events`.
